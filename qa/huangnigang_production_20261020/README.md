## 复现入口

以下是执行方法，不是通过记录。在工程根目录运行`python -X utf8 -B qa/huangnigang_production_20261020/run_batch.py`：

1. `prepare`返回新的`run`目录；记录为`$hgRun`。再执行`import --run $hgRun`，只对该冻结副本导入和生成内容身份。
2. `source --run $hgRun --phase model`核对运输守恒；`source --run $hgRun --phase live --timeout 600`产生真实酒计路线和两份在途检查点。
3. 用上一步报告作为`--producer`，分别运行`cold_carried`、`cold_empty`、`faults`、`empty_faults`、`ui`。空车两个驱动另加`--fixture-kind empty`；每次自动创建独立进程与私有用户目录。
4. `prepare --legacy`另建真实Git基线副本，导入后运行`source --phase legacy`产生原三担档。当前副本的`legacy_reject`使用该报告并加`--namespace hg_legacy3`，检查实际拒绝和文件不变。
5. `export --run $hgRun`生成新完整包；`packed --run $hgRun --phase live --export-receipt <导出收据>`用原样编辑器二进制加载实际编译PCK并执行外部驱动，产生包内检查点。其冷恢复、故障和UI验证使用包内报告，不能混用源码检查点。这条路径明确记作`compiled_pck_editor_loader`，不算原版发行EXE验收。
6. `release --run $hgRun --export-receipt <导出收据> --timeout 1200`启动原版Windows发行程序，使用独立私有用户目录和普通游戏窗口；窗口操作、画面及结局另记验证记录。原版模板禁用路径覆盖，会忽略`--script`，不能用该参数假称自动驱动已运行。

编译包`live`成功后，可将其余检查串行合批：

```text
packed-suite --run <冻结目录> --export-receipt <导出收据>
  --producer <成功的compiled live报告>
  --legacy-producer <成功的旧三担报告>
  --phases model cold_carried cold_empty faults empty_faults legacy_reject ui force_departure
  --timeout 600 --wait-lane 1800
```

上述命令换行为展示用途，实际作为同一次调用传入。整批只在开头、结尾各完整扫描根源码、
冻结源码和导出资源，持续持有本批引擎锁，减少重复扫描；每阶段仍是新进程、新隔离用户目录，
独立日志、报告和收据。外部GD及bootstrap在整批开始时冻结，生产者、阶段报告及日志SHA纳入尾检。
首次失败停止后续阶段，但仍完成尾检。阶段收据须与整批最终成功收据一同使用，
不能把局部阶段或Python替身模拟当作整批原生通过；此路径仍不算原版发行EXE验收。

每步输出唯一`receipt.json`。失败保留并先修原因；生产源码变化必须重新冻结，旧成功结果不转授新版本。完整结果及直接目检完成后更新上方清单。

旧`tools/level1_world_restore_qa.gd`和`tools/level1_cross_process_qa.gd`使用三担v1及旧接口，
不是本批七车十一担v2的验证入口，待完整战役续玩批迁移。本批仅使用上列绑定实际生产资源的驱动。
