# 本批针对性原生驱动

这些是外部 QA 命令驱动，只运行冻结工程或冻结导出包中的实际生产资源。`bootstrap.gd` 在真实 autoload 就绪后加载 SHA 清单所绑定的 Node 驱动。编写本目录不代表原生测试通过；实际状态以父目录本批各阶段原始日志和报告为准。

## 运行约定

- 原生运行由根任务串行调度，共享引擎占用检查与锁由统一 runner 执行。本目录驱动不自行启动另一个 Godot。
- 四个根 `APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP` 必须分别指向 `ART_QA_PROFILE` 下同名小写目录；要求 `STEAM_DISABLED=1`、`CAMPAIGN_QA=1`。拒绝使用日常玩家数据目录。
- `HG_WORKER_ROOT` 是运行副本中这些 GD 文件的绝对目录，`HG_WORKER` 是其中目标驱动；`HG_QA_BINDINGS` 是相邻所有参与 GD 文件的 SHA-256 JSON 字典；入口参数为 `--script <bootstrap.gd绝对路径>`。
- `HG_SOURCE_MODE=1` 验证实际源工程身份；`0` 验证实际 Windows 编译包身份，并要求 `HG_EXPECTED_IDENTITY` 与 `HG_EXPECTED_EXE_SHA`。包内驱动由原样编辑器二进制加载PCK，明确记录为 `compiled_pck_editor_loader`，`native_release_tested=false`；原版发行EXE另做窗口操作验证。不能为了通过而注入内容或引擎身份。
- `HG_REPORT` 指向本次唯一报告，`HG_OUTPUT_ROOT` 为本次输出根；`HG_ROUTE_OUT` 是截图目录。`HNS_SIZE` 默认 `1280x720`，`LSH_LANGUAGE` 默认 `zh_CN`。

## 驱动和实际断言

| 文件 | 操作与范围 |
|---|---|
| `live.gd` | 正常时间倍率 1。真实进场、照看枣车、杨志盘问、白胜自行挑酒落担、三人酒计；15 名押送者存活麻倒。七星各自实际取原空车，再将原车推到货物处装载；同进程原车用对象引用核对，11 原担才使用Unit唯一ID；七车全部实际送达、8 人收队。各类进度都通过实际玩家命令及正常 tick 产生。三段开场各核对四语，共12组实际控件；真实结局切换四语，逐语核对71条完整战报及结算数据不变，预期直接取catalog与普通格式化，不使用格式历史。保存四张开场和四张结局代表图，全部战报不由单张可见截图替代。 |
| `force_departure.gd` | 同一份源/包驱动，倍率1。从真实开局集结七星、主动攻击进冈押队并以实际战斗制服15人，记录8名同伴实际存活/阵亡及原始身份；由存活原主人或当前动作许可的空手幸存七星逐辆取7原车、移动装11担并全部交付，核对21个真实动作、原车/纲担身份、加权计分与解绑。选一名存活七星先完成自己的原车，再通过玩家移动和据守命令留在远处并排除后续接力；其余幸存者到西口后验证不会自行胜利，由另一存活七星完成真实 `withdraw_now`，核心胜利但酒计、全员出冈等4个原著目标未完成。自然死亡接力仅按实际阵亡及已完成接力动作报告覆盖，零伤亡不宣称覆盖；不注入伤害、位置、任务或结果，不新建存档/截图矩阵。 |
| `cold_empty.gd` | 新 OS 进程读取 `live` 冻结的第7原空车在途档，验证7原车、7主人和11原担；继续实际装第7车，保持六辆空车和一辆载货车，再用真实 Session 写下一代存档。 |
| `cold_carried.gd` | 新 OS 进程读取 `live` 冻结的第7载货车在途档，验证7搬运者和11担；真实继续第7车送达，只记1担，重复完成请求不重复计分，再真实保存下一代。对这份真实世界的两个内存深拷贝分别删除第7车交付事件、添加未交第1车事件，通过实际 Codec 编解码和 Core.prepare 验证 `LEVEL1_DELIVERY_FACTION` / `units` 拒绝；完整原槽 journal SHA、当前任务事件、单位阵营和实际计分保持不变。 |
| `faults.gd` | 从自然路线的载货档独立恢复。只故障注入吴用、阮小七的致死伤害，调用实际死亡回调，验证双担/单担原车落地和接力；晁盖完成自己车后走回接车，经过实际寻路和交付得到2→3→5→11担。完成判定检查真实持久动作事件；交付另核对对应车事件、精确担数增量、解绑、原担可见及阵营，最后检查七车十一担进入收队。3担不能提前结束，重复交付不能计分。此分支不声称八人生还。 |
| `empty_faults.gd` | 从自然空车在途档独立恢复，第7原车与主人继续实际移动后，只注入其主人致死伤害。验证原车同一对象精确留地、停止跟随、11担未动；死亡后新接车动作、标记与按钮显示“幸存七星”，并在同一运行切换四语言核对实际显示。晁盖实际装/交自己的双担车后走回接该原车，再推到货担旁真实装货，并再保存。拒绝白胜接车、一人双车与死者旧装货命令。 |
| `model.gd` | 生产运输模型的独立组合检查：5^7=78,125种空车在地/空车推动/载货在地/载货推动/已送达组合；七车和十一独立货担守恒；非法重叠、重复主人、白胜推车和重复计分拒绝。同一驱动通过实际 `prepare_runtime` 注册固定短语，取车/装货/送达三个代表短语各做4种旧语言到4种目标语言的 `Localize.text` 与真实嵌套通知翻译；旧短语不写入格式历史，重复准备不得改变既有别名或任何普通目录译文。模型通过不能替代真实场景证据。 |
| `legacy.gd` | 只在旧生产基线独立工程运行：实际生成3担、v1 profile，真实屏障与Session保存并冻结记录；禁止将当前v2改标签当真实旧档。 |
| `legacy_reject.gd` | 当前生产工程/包读取上一步真实旧档，经当前Session拒绝；完整文件清单、路径和SHA前后相同，菜单保留。 |
| `ui.gd` | 从自然路线冻结的载货档独立恢复，四语言×1280×720／960×720／1920×1080×单人／七人选择，共24组实际画面与截图。核对任务面板和底栏间隔、七车按钮译文、原存档SHA不变；截图仍需直接目检，不以矩形断言替代。 |
| `controls.gd` | 在实际场景中通过 `Window.push_input` 派发键鼠，确认引擎真实 tooltip 出现后首按 Esc 能暂停、时钟冻结、恢复不二次暂停；继续检查指向取消、离开确认、设置和库存既有行为、捕获屏障 REQUESTED/HELD 的输入守卫及返回主菜单。包含四语矩阵之外的英文群选完整标题悬浮显示。未观察到真实 tooltip 即失败；这不代表桌面操作系统按键或原版发行 EXE 验收。 |

## 冻结存档输入输出

`live` 先在第7空车移动超过8逻辑像素、原车节点移动超过5像素时写入空车在途档；六辆其他空车不接到装货命令。输出到 `HG_EMPTY_COPY`，报告为 `empty_checkpoint` 与顶层 `empty_fixture_files`。

随后七车实际完成装货；第7载货车单独接到出冈命令并移动超过8像素时写入载货在途档，六辆其他载货车仍待命。输出到 `HG_CARRIED_COPY`，报告为 `checkpoint` 与顶层 `carried_fixture_files`。之后自然完成全部运输和收队。两次快照都冻结完整 journal 与 lifecycle 后才继续，因此冻结副本不会被后来胜利结算改变。

`HG_EMPTY_COPY` / `HG_CARRIED_COPY` 必须是 `HG_OUTPUT_ROOT` 下尚不存在的子目录。第二次保存会保留此前 journal：载货副本通常有3份JSON，不应写死只有2份；空车与旧档首次保存通常有2份。

原枣车是 `Node2D`，不具有 Unit 的 `entity_id`。checkpoint 的 `cart_tokens` / `cart_states` 来自实际落盘的 Level.external.jujube_carts 与 Visual.hg_cart 记录；跨进程通过真实 `run_level1_visual_state.tokens(level)` 对照 `ext:level1:jujube_carts:0..6`、位置、可见性和cart_index。同进程只比较原车对象引用；不把 `get_instance_id` 当跨进程身份。

两个 cold 驱动、`faults` 和 `empty_faults` 要求 `HG_COLD_EXPECTED=<live报告>`。runner 必须在不同私有 profile 中按报告逐文件核对SHA后复制相应冻结副本到 `Godot/app_userdata/水浒英雄传：八幕战役/hg_transport_world/`。`cold_empty` 和 `empty_faults` 读取报告 `empty_checkpoint`，其他读取 `checkpoint`。必须检查消费者 PID 不同、实际内容身份相同、读回槽SHA与原冻结槽一致；不同引擎或改动后的源内容不拼接证据。

旧生产 `legacy.gd` 要求 `HG_LEGACY_COPY=<HG_OUTPUT_ROOT下新目录>`；旧档拒绝要求 `HG_LEGACY_EXPECTED=<旧生产报告>`，将该报告 `copied_fixture_files` 对应文件复制到当前私有 profile 的 `hg_legacy3/`。

## 局限

内部保存显式将真实屏障配置为黄泥冈官方 context，Steam禁用且只有隔离的uncredited生命周期；公开战役继续按钮不因此开放。这不是全战役61阶段、真实Steam账号/云同步、完整奖励验收或真人鼠标试玩。载货与空车死亡都明确属于故障注入，不作为自然酒计八人生还证据。所有图像仍需直接查看，截图保存或矩形断言不代表美术人工接受。

分支覆盖以实际执行入口为准：`live.gd` 当前只执行酒计；其历史保留的强夺函数体不算本批运行覆盖。`force_departure.gd` 单独补自然强夺与先行收队，使用通用运行变量且不需要 `HG_COLD_EXPECTED`。故障与冷恢复驱动仍只覆盖各自明确列出的运输检查点。

`empty_faults` 的真实输入中7人均已取车，故标签专项验证的是空车主人死亡后新注册的接车动作；不据此宣称已验证尚未取车主人死亡时旧动作的标签刷新，也不宣称已独立冷恢复死亡后的标签档。
