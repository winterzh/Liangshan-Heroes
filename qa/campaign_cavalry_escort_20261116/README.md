# 连环马：护军候骑、随行与退守

## 行为

两座原辎重营继续按原间隔和真实军资训练，原人数上限与成本不变。护军先到本路甲马后方集结；原骑队出发后，步军通过攻击移动跟随该路现存甲马的平均位置后方96像素。快骑和步军保留各自速度，因此玩家可以把甲马引离护军。跟随目标变化不超过96像素时不重发命令；候骑到位后清除旧攻击移动终点，避免通用进攻看门狗重新驱赶；嘲讽期间由Unit接管强制目标，不覆盖其指令；眼前视距内且未隐身的交战不被跟队打断。

本路六骑全部被击溃后，原有护军使用普通移动退到大营附近；回营后仍可交战守营。大营已破时退向尚存的本路辎重营，两者皆失时留守本路。营地破坏仍只停止后续补兵，不删除在场步军。没有瞬移、回血、免费补兵或新一批甲马。

派兵位置只读取己方骑兵、己方营地和固定路点，不读取玩家迷雾缓存或追踪隐身敌人。普通Unit索敌照旧。三个护军阶段的提示接入既有查看面板，四语来源campaign_cavalry_escort.json同步catalog。视野外不显示阶段。

角色阶段从既有waves、十二骑身份/存亡及护军source_lane实时派生。普通移动、攻击目标与路径继续使用既有Unit保存结构，不增加Level字段或计时器；声明分类检查覆盖本批。生产内容身份改变，旧冻结候选不沿用，不授完整续玩资格。

attempt1的定向检查通过，正常路线推进至首路接战前后；随后代码复核发现旧攻击移动终点会触发通用进攻看门狗，以及退守可能覆盖嘲讽。主动终止本批进程修正，不将该次中断记作整关通过。原日志、收据、截图及来源摘要保留。最终入口增加这两条约束后复验。

attempt2的20项夹具中19项通过，1项失败：新增嘲讽夹具仍把步军放在营地160像素防守范围内，嘲讽解除后保留眼前战斗符合规则，却被夹具错误要求继续后撤。早先只读日志尾部漏看该项，收尾逐项核对时发现；此批不能记作20项通过。英文窄窗截图已生成，无脚本错误。整关部分另因加速设置在场景初始化前被重置而主动中断。原夹具在attempt2/fixture.gd.txt，后继把嘲讽夹具移到前线，明确与“回营可交战”检查分开；生产规则未因此修改。

attempt3为已修正加速的原defend路线：261.88秒退出1、无脚本错误；900游戏秒内12骑均钩破并击溃、中军1500生命，但未攻破大营。21名护军正常付费训练，玩家付费训练85单位，直接围攻敌将后持续在前沿集结导致损失、军资耗尽。两路护军都实际经历候骑、随行、失骑退守，原报告含角色转移时点与实体ID；没有基础胜利资格。

后继驾驶改为：每至多6秒下令，避免反复打断交战；反攻前回后方集结，兵少于12重整，实际到齐18人后进攻；依序考虑付费招募花荣、林冲（最终本次仅实际下单花荣），反攻兵种增加弓手；步军攻击移动掩护，攻城器械单独点大营，避免全部追打敌将。初始守两路、真实资源与全部生产/技能规则保持。新策略在本批专用工具中，旧defend策略保留。
