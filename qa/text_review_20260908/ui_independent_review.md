# 独立 UI 复核

2026-09-08；只读复核主任务本轮 `menu.gd`、`codex.gd`、`editor.gd`、`scenario_editor.gd`、`hud.gd`、`settings_panel.gd` 与 `text_ui_review.gd`、`battle_text_ui_review.gd`、`text_review_contract.gd` 差异。未修改生产代码或主任务探针。

## 可复现问题

### 场景编辑器单位分类未本地化

- 位置：`scripts/scenario_editor.gd`，`_build_unit_picker()`，原审查行 149–152。
- 步骤：语言选英文或日文，进入场景编辑器，点“放单位”或“放增援”。
- 结果：分类仍显示“天罡”“地煞”“英雄·大将”“兵卒”“建筑”。按钮先把 raw 分类值和箭头、计数组装成一个字符串，完整组合没有词库键。
- 建议：内部分类键不变，只翻译分类名称后组装；关注较长英文分类令三列按钮扩宽的效果。
- 证据：`scratchpad/ui_independent_review/en/tool_reinforce.png`、`ja/tool_reinforce.png`。

### 自编单位名称被界面词库误译

- 位置：`scripts/scenario_editor.gd`，`_key_opt()`，原审查行 1048–1055；同类单位列表按钮也应覆盖此边界。
- 步骤：创建一个自编单位，名字恰好为“返回菜单”，把它加入一波敌军，在英文或日文界面查看单位下拉。
- 结果：配置原名仍为“返回菜单”，但下拉显示 `Back to Menu` 或 `メニューに戻る`。`_display_uname()` 已返回自编原名，随后原生 OptionButton 自动翻译再次解释它。
- 建议：自编名字作为用户数据，关闭 OptionButton/PopupMenu 的自动翻译；内建名称先显式翻译后显示。单位选择列表和单位标题采用同一边界，禁止仅修改配置值来修显示。
- 证据：`scratchpad/ui_independent_review/en/custom_name_collision.png`、`ja/custom_name_collision.png`；图中真实波次下拉和一个使用相同工厂的独立下拉均复现。探针断言 cfg 原名未被改写。

## 实测范围与限制

- Godot 4.6.3 Compatibility，独立应用数据目录，英文/日文各 12 个截图：8 种工具、添加波次后、波次滚动到底、名称碰撞、单位属性弹窗。两次最终进程退出 0，Godot 脚本错误 0。13 个探针检查主要证明截图生成和配置原名不变，不代表上述视觉问题不存在。
- 查看了英文地形、增援、波次底部、属性弹窗、名称碰撞，以及日文增援、名称碰撞截图。其它已生成截图没有逐张视觉验收，不称全部通过。
- 1280×720 未见上述工具和波次操作被横向截断。英文加入一组敌兵后，画布宽从 564 降为 335 像素；控件仍能容纳，但可考虑缩短下拉最小宽度或让波次组换行。此项是布局改善建议，不列作阻断缺陷。
- 主任务探针的 scenario 默认路径没有切换全部工具、没有加入波次组，也没有用户名称恰好撞词库的样例，因此两处问题可在原有探针全过时存在。建议将这两个边界加入回归覆盖。
- 此次使用函数驱动建立页面和读取布局，未把所有按钮真实鼠标点击、键盘焦点、滚轮路由或系统触摸手势算作已验证。主任务其它菜单、结算、全部技能卡的已运行结果仍由主任务报告；独立静态差异复核未发现另一项足以确定的交互回归。

独立探针与输出均在被忽略的 `scratchpad`；修复后的复测由主任务安排，本文记录修复前证据。
