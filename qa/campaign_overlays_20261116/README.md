# 战役任务、消息与生产底栏布局

2026-11-16，基于 efad12defb257165235da4cb20a044840cb3fd28，M7局部整合。此前大名府、连环马截图显示：任务与消息按固定底栏高度避让，英文单位详情换行时仍盖住指令区；960窗口选中生产建筑还会把底栏撑出右边界。

## 本批行为

任务正文根据实际底栏及待排版最小高度缩短为滚动区。消息记录也使用剩余高度；短暂预览按可用空间显示最多三行，超长文字用省略号，完整内容和历史记录仍保留在“展开信息”。消息区域同时避开展开任务和顶栏；完整记录展开时不再叠放键盘帮助。

桌面紧凑布局由英雄扩展到工人和建筑，保留按钮顺序、快捷键及原训练/取消逻辑。英雄1100以下、其他指令1400以下、带队列1800以下使用紧凑布局；指令三列，生产队列两列滚动，原八项队列全部保留，宽屏恢复原列数。没有修改经济、关卡目标或新增保存字段；HUD构造增加一个队列滚动容器。公共生产输入已改变，旧冻结续玩候选资格不沿用，本批未开放公开战役继续。

## 验证范围

定向实际渲染91项通过，50.05秒、退出0/脚本错误0；十张图覆盖四语、960窄窗、展开记录、满八项队列及末项取消退款、1920宽屏恢复和非战役模式。最终结果见 final/report.json、receipt.json、render.log及实际渲染PNG。在实际大名府场景冻结战斗、经济与镜头后，刷新真实英雄栏/资源栏并展开任务；检查简中1280×720、英文960×540、日文960×540、繁中1440×900、英文完整消息、生产建筑、满队列、宽屏1920×1080、空选择与真实非战役skirmish界面。满队列夹具先补2000金木、人口上限设100，再通过普通付费API排八名工人，滚动到最后一项并调用原按钮执行取消，检查队列减少和原价退款。它是界面操作夹具，不是正常经济或实战证明。

最终截图逐张目检。原旧部署消息及乔装姓名等仍有未翻译文本，列入后续四语补齐；本批不将其标为全语言验收。冻结场景截图不授帧率/性能、完整恢复、八章通关、真人体验或触屏/Android资格。没有运行旧52/61全量矩阵、修改其他工作树、合并main或发布Steam。

## 过程原件

- attempt1：独立SceneTree脚本在自动加载前引用Localize导致编译失败；夹具改从根节点取实际Localize。
- attempt2：46项中英文预览底边间隔不足一项失败；行高估算未算主题行间距，修正生产代码。此批截图还发现建筑底栏宽度溢出，随本批修复。
- attempt3：新增队列夹具使用错误的工人字段/键导致空数组访问，手动终止自有Godot进程；修正为Defs真实worker字段，未改变普通训练条件。
- attempt4：81项通过，但目检发现冻结夹具未刷新英雄栏和初始资源值，不能作为有完整英雄栏时的布局证明；保留原报告，并加入实际刷新与英雄栏存在检查，最终证据在final。

- attempt5：补齐真实英雄栏后的91项中90项通过，一项误要求遭遇战开局必须有英雄；该模式实际从基地和工人起步。夹具改为核对实际英雄数，无生产修改。

复跑：`python qa/campaign_overlays_20261116/render_runner.py --godot <Godot路径> --lock <共享引擎锁>`。Godot4.6.3、gl_compatibility实际渲染；独立APPDATA/LOCALAPPDATA/TEMP/TMP，禁用Steam。排他创建锁且只释放自己持有的锁，只终止自己的超时子进程。最终来源哈希记录于source_manifest.json。
