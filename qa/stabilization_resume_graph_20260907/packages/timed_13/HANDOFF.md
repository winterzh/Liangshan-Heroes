# Timed visual candidate: eight additions

Candidate only. No production, public documentation, player files, Git state or engine process was changed. `prepare.py` verifies the immutable first visual package, uses its exact 27-file overlay copied into this package, checks the eight declarations against explicit fields and parses the resulting scripts. `static_preparation.json` records grammar checks, not native acceptance. Production-before bytes are rebound to ROOT's integrated `61f8f557cb19e5f6483f468ba3435767a2108584` stable identity and defense v2 baseline; `before_binding.json` records each actual raw digest.

The R4 native diagnostic identified only `visual.records/0/node/name` in all eight original visual cases: the two roots shared one parent, so Godot renamed the second FxRoot. `topology_evidence.json` pins that report and verifies all eight recorded attachment/lifecycle differences plus matching arrays and sampled Unit state. Both legacy and timed fixtures now use separate source/restored stages with the same transform. They additionally check distinct parents and both exact FxRoot names. All original record/name comparisons remain strict; the visual codec and production candidate were not changed to hide this fixture mismatch. This topology fix still requires the scheduled native attempt.

The original five classes retain their exact field, reference and lifecycle meanings. The only correction inherited from the independently diagnosed visual R3 is `refs["chain_from"] = tag.value`: the general codec still rejects StringName keys. The legacy driver also uses a String key for its deliberate extra-field rejection; its unsupported-class example now uses StompFx because AbilityFx is implemented here. The original frozen package remains unchanged.

All eight current classes are leaves. Internal or normal child nodes are rejected, never omitted. The Battle delta consists solely of eight restore-only ready guards. Prepared nodes are signal-blocked and disabled; all values are assigned before paused attachment. The marker prevents ready from resetting time, moving a meteor to its start, recalculating projected geometry or regenerating particle arrays. Activation removes it. New-class capture requires ready to have completed and no restore marker to remain. Unsupported material, inherited-material, filter, repeat, light, visibility-layer or child-clipping overrides are rejected.

Ground fire requires explicit root participation: the source graph constructor receives the exact Battle owner; capture verifies the complete graph's fire count equals `Battle._ground_fire_visuals` and each ground-fire node has precisely the current zero-flag tree_exited callback. After preparing into an off-tree Battle and installing its exact saved counter and `fx_root`, the host calls `bind_ground_fire_owner(owner, count)` once before attachment, including count zero so later actual ground-fire creations retain owner validation. A count mismatch or second bind fails. Activation refuses ground-fire nodes without this binding. The host must discard the whole private transaction on any failure; it must not activate a graph whose root fields, callbacks or arrays remain unbound.

Building textures are supplied by the trusted host as opaque key -> actual immutable Texture2D. The save cannot request resource loading. Capture requires exact object membership; validation compares the key plus recursive AtlasTexture base, region, margin, clip, dimensions and installed resource path. Supported leaves are imported CompressedTexture2D under assets or content/art; generated textures, arbitrary resource types, missing registrations and changed signatures reject. The host must establish those registrations from its verified content identity before reading save tokens, never build the trusted map from saved keys or paths. The native fixture uses actual Art.building_texture("barracks"). Ward rendering calls Art directly; its current Art-produced texture/fallback signature is also checked. Resource-byte integrity, Art singleton state, effects-quality settings and fallback font belong to the surrounding verified content/render environment.

Three standalone driver entries are frozen for the generic overlay runner, copied outside `.gdignore`:

- `timed_smoke.gd` -> `res://tools/stabilization_visual_timed/timed_smoke.gd`, suite `timed-effects-visual-candidate`, prefix `[timed-effects visual candidate QA] `.
- `visual_smoke.gd` -> `res://tools/stabilization_visual_timed/visual_smoke.gd`, original five-class suite and prefix.
- `item_smoke.gd` -> `res://tools/stabilization_visual_timed/item_smoke.gd`, original item suite and prefix.

Each requires a fresh private profile/report and complete source/engine/PID/player guards via RUN_RESTORE_QA_MANIFEST. No Battle ready is called. The timed driver uses actual off-tree Battles, real Units and baked maps, actual skill/death creators, real Unit graph + meteor/ward and continuous-effect modules, JSON roundtrip, paused visual attachment, then 65 paired calls to actual consumers and visual process bodies. The building-death fixture supplies an actual off-tree HUD with only its unrelated empty-selection labels and portrait control; it does not substitute the death or Fx creator. Cases cover meteor continuation, normal/lite ground fire, healing and both banners, arrow flight/impact, rain, flameburst, ability and collapse. Rejection cases cover unknown classes, malformed/nonfinite/lifetime/particle state, StringName keys, internal children, missing or illegal textures and duplicate/mismatched ground-fire owner binding. Snapshot equality after attachment tests preserved prior random layout; a real global RNG successor sentinel tests that visual prepare/ready draws nothing.

Future visual creation in each paired timestep uses the same explicit test-only global seed. This is a declared fixture policy, not a global visual-RNG save solution. Gameplay RNG is independently restored from its real snapshot and compared throughout. This driver cannot prove full engine scheduling, a render frame, root clock barriers, deferred events, a cross-process player slot or long gameplay replay.

An attack/poison/death WardFx itself is supported, but its next actual offensive pulse creates BlinkShotFx, outside these eight. The driver executes an attack pulse, checks its real damage and BlinkShotFx creation, then requires the next whole visual snapshot to reject. This is an explicit incomplete future-visual dependency, not a skipped node or a claim that attack wards have a complete resumable chain. Other current unsupported visual classes remain fail-closed as before. Actual Projectile, LiBrawnAxes, scenery/world nodes, death-remains holders and full paused-root scheduling are separate factory work.
