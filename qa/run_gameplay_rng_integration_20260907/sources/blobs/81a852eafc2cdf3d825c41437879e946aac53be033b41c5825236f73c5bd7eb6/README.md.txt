# Gameplay RNG callsite QA

Prepared for the integrated production candidate. No engine result is claimed by this preparation. Root owns actual execution and any subsequent source fixes.

Run from the checkout with Python 3.9 or later and its UTF-8 mode. `--freeze` records the already applied production files; it does not apply a candidate or run Godot. It preserves prior pins under `pins_history/`. After any reviewed production fix, explicitly freeze again; never reuse a run's old source claim.

```powershell
python -X utf8 scratchpad/run_gameplay_rng_callsite_qa/run_qa.py --freeze
python -X utf8 scratchpad/run_gameplay_rng_callsite_qa/run_qa.py
python -X utf8 scratchpad/run_gameplay_rng_callsite_qa/run_qa.py --run --godot $env:GODOT_PATH --phase matrix
python -X utf8 scratchpad/run_gameplay_rng_callsite_qa/run_qa.py --run --godot $env:GODOT_PATH --phase startup
python -X utf8 scratchpad/run_gameplay_rng_callsite_qa/run_qa.py --run --godot $env:GODOT_PATH --phase restore_reject
python -X utf8 scratchpad/run_gameplay_rng_callsite_qa/run_qa.py --run --godot $env:GODOT_PATH --phase pair
```

`GODOT_PATH` must name the actual non-console Godot executable with the reviewed engine hash. `--phase all` executes the five phases serially and stops on the first failure. No process may be run while another task owns the shared lock. Each run gets a new directory, each phase a new private APPDATA/LOCALAPPDATA/TEMP profile. The runner checks source paths and bytes, actual executable hash, real Popen PID, private user path, protected player data, strict UTF-8 logs and all required labels. It polls its own log for engine/parser errors and confirms the exact child has exited before checking exclusive ownership and releasing the lock. An unconfirmed exit or changed protection boundary keeps the failed run and lock for inspection.

The driver loads the actual production provider after Autoloads are ready. `resolve_runtime_identity()` must independently return a save-eligible installed identity and its observed engine hash must equal the host's actual executable SHA. The save's compatibility record never supplies trusted identity. Sources are checked before and after each phase, including all current `scripts/**/*.gd`, `scenes/**/*.tscn`, `project.godot` and the driver. The reviewed full production source receipt additionally guards content/resources. No source mirroring, fake Unit, fake Battle or replacement RNG is used.

The runner directly uses the current checkout through `--path`; it neither copies production nor imports a new project. It reuses that checkout's existing `.godot` import cache, which is outside the immutable source receipt and may gain ordinary engine runtime cache entries. There is no cache-speed or cold-start claim. Before the first run, root must finish the coordinated normal import of the integrated source and its canonical UIDs. Source-side `.gd.uid` changes during a run are rejected by the full source guard. The actual `project.godot` Autoload mappings run unchanged, including `AndroidUpdater`, Settings, Campaign, Art and Steam services. Updater automatic network checking is disabled by the reviewed QA environment; its actual installed script and the provider remain in the source pins and execute normally against the fresh private profile.

- `matrix`: independent instances of the formal native RNG check the actual checked API and consumer draw order. Covers four draws per spawned unit and its real `order_amove`, zero draws for the classic 30-wave table, random-wave modulo and short-circuit arithmetic at indices 0/1/2/5/6/12/29, drunk immediate and next-step rolls, misses/evasion/critical/bash/cavalry/lifesteal, explicit axes roll, unrelated global visual noise, and real Projectile/axes one-hit/deletion behavior. The selected random-wave sequence is compared exactly; it is not a claim that every possible random branch outcome was sampled.
- Exhaustion is injected by restoring a valid native RNG record with its call count at or just before the signed int64 limit. The real module then raises `CALL_COUNT_EXHAUSTED`. The assertions check no default value, no next Unit step or UI command, no next target/effect, no wave advance or half cache commit, and denied capture. Damage before the fault remains visible; this is intentionally not an atomic rollback assertion.
- Unit R1 asserts immediate stops after real inventory periodic callbacks, the production death signal callback, the first passenger's real `leave_garrison`, and summon expiry. `Defs.ITEMS` is currently empty, so one explicit data-only passive fixture is inserted into each isolated Battle's item table and consumed by the real Inventory/Battle methods. No random result or callback is stubbed.
- `startup`: executes a full original new Battle `_ready` with a real map/HUD/deployment, observing the actual HUD and Unit insertion events to check RNG/level ownership already exists. Its generated three-wave random cache is compared to the independent RNG started with the actual new-game seed. This headless source test is not a visual or click-through UI acceptance test.
- `restore_reject`: separately attaches both accepted and rejected restore-preconfigured Battles through the real new-game entry. Both must report `RESTORE_FACTORY_REQUIRED` without map/HUD/units/Steam run creation.
- `pair`: writer and reader are distinct actual processes and profiles. Writer performs a prefix, stores the formal RNG record as JSON, then records a real callsite suffix. Reader resolves the installed identity afresh, restores only that RNG record into newly constructed controlled fixtures and compares the exact suffix trace and final codec record. Writer report and handoff hashes remain bound throughout. This does not restore Battle/Map/Unit state.

Each run preserves `receipt.json`, source/player before/after receipts, phase manifests and environment controls, complete logs, process receipts and JSON reports. Pair additionally preserves `handoff.json`. Failed runs are never overwritten. Reports use suite `gameplay-rng-callsites` and the single stdout prefix `[gameplay-rng-callsites QA] `. Do not archive `private_profile/` or player directory listings as public evidence without the root's normal whitelist review.

`unit_r1/` contains only the four additional guards relative to the older frozen Unit candidate. `receipt.json` binds its original production base, prior candidate, final candidate and exact inverse restoration proof. Production declarations remain unchanged. The old candidate and its pins are left intact. This directory contains no production promotion, PCK validation, complete world continuation, performance acceptance or release claim.
