# 出征与模式进场卡顿量测

2026-11-16 在 Windows 源码版复现「剧情模式 → 三打祝家庄 → 出征」卡顿。来源提交为 `07df0d968a5c50d30a2717bee8bc557bd609a4d0`，Godot 4.6.3，兼容渲染器，RTX 4060 Laptop，1280 × 720，简中和独立离线存档目录。同一进程返回主菜单后重复进入，结果如下。

| 时间区间 | 首次 | 再次 |
| --- | ---: | ---: |
| 打开剧情选关页至画面绘制 | 35.06 ms | 13.89 ms |
| 出征至战斗节点加入场景树 | 4.65 ms | 2.27 ms |
| 战斗节点加入场景树至场景就绪 | 45,185.42 ms | 20,131.58 ms |
| 场景就绪至战场首帧 | 658.06 ms | 34.49 ms |
| 出征至战场首帧 | 45,848.13 ms | 20,168.33 ms |
| 跳过三页开场说明后，开始战斗至开打画面 | 22.32 ms | 7.41 ms |

两次从点击出征到场景就绪期间均绘制 0 帧。脚本发出实际按钮的 pressed 信号，用 Godot 单调时钟在节点挂入、场景切换完成和渲染完成时取时间戳。启动日志有 GLES3 不支持 2D MSAA 的警告，祝家庄样本进程退出 0。批次随后因其他任务启动 Godot 而结束，驻守战、1v1 对战和竞技场等待实测。

本机安装 Build `26699320`，Windows Depot `5088121`，Manifest `3231099744923356430`。用外置脚本启动后，90 秒内未产生计时记录。另一次无外置脚本的隔离启动已创建游戏窗口，Windows 锁屏遮挡窗口，未采集按钮与首帧。Steam 正式版实际出征耗时仍待实测。

## 场景初始化分段

在同一源码提交的独立副本加入[单调时钟定位点](source_profile.patch)，再走一次祝家庄首次及重复出征。两次场景初始化耗时 45.287 秒和 19.727 秒，其中运行内容身份解析约 44.834 秒和 19.373 秒。下表用两个独立时基分别计算区间，原始时间戳保存在[分段数据](entry_profiles.json)。

| 阶段 | 首次 | 再次 |
| --- | ---: | ---: |
| 源码文件树扫描与校验 | 44,313.410 ms | 18,879.354 ms |
| Godot 编辑器运行文件哈希及前置检查 | 475.615 ms | 459.934 ms |
| 地图构建（含场景环境） | 337.722 ms | 290.518 ms |
| HUD 搭建至部署起点 | 78.355 ms | 33.277 ms |
| 初始部署 | 12.070 ms | 8.143 ms |

源码扫描占场景初始化时间约 97.85% 和 95.70%。源码文件树所耗时间包括首次枚举与内容哈希、规范化以及复核枚举。复验时在独立检出对固定基线使用 `git apply --unidiff-zero --check` 和 `git apply --unidiff-zero` 加入计时点，运行同一 `level3` 路径，从日志提取 `ENTRY_PROFILE`。

## 正式包可执行文件的单项测量

用同版本 Godot 的 `FileAccess.get_sha256()` 对本机 Steam Build `26699320` 的 `LiangshanHeroes.exe` 逐字节读取并计算 SHA-256，共 1,827,144,096 字节。连续两次分别用时 5.904 秒和 7.230 秒，摘要一致。该步骤与打包版身份解析中的可执行文件哈希调用相同。这里观察的是独立无头进程对文件的计算耗时，实际进场仍须从正式界面采样。交付的[脚本](measure_executable_hash.gd) 可在空 Godot 项目使用 `--headless --script <脚本路径> -- <游戏可执行文件路径>` 复测。

## 复现与下一步

以已完成资源导入的独立源码检出为 `--project`，使用 Windows Godot 4.6.3 控制台程序，`--lock` 指向项目共用引擎锁，`--output` 使用新建批次的路径，`--modes level3` 仅重复本样本。运行 `python run_entry_timing.py --help` 查看其他入口。脚本、[采样原始字段](source_zhujiazhuang.json) 和 [开发计划](../../docs/DEVELOPMENT_PLAN.md#2026-11-16-出征与模式进场卡顿) 配套保留。

下一轮优先实测正式包点击反馈与战场首帧，并验证将身份计算中的文件校验移出界面主线程的方案。保留进场身份、存档时复核及恢复时拒绝不兼容文件的一致性。比较优化前后的点击反馈、总耗时及重进路径。
