## 验证与目检

- 完整比较 187 个定义的 UI、avatar、portrait、building、unit、terrain，以及 45 个命名变体的 UI、avatar、unit；仅三种基础物件的 UI/avatar 六项允许变化。路径、文件哈希、尺寸、图集区域、边缘过滤均纳入比较。
- 三个修订图标必须与各自现有建筑/地形纹理相同。187 个定义仍有可用 UI；错误的法场变体身份继续拒绝。
- 使用真实图鉴 `_select` 和 HUD 渲染器，检查三种无变体物件。实际当前第二、三、七、八幕检查江州刑台、白龙庙、祝家庄两座门、四处酒望、快活林招牌、大名府门的专用 UI 路由。
- 13 张截图已核对：新旧/32/64/大图对照 1 张、图鉴 3 张、基础 HUD 3 张、战役 HUD 6 张。最终 11 张与已目检版本逐字节一致；最终两座城门截图直接目检。详见 `visual_review.json`。
- 暂停场景后关闭迷雾覆盖不会自动刷新敌方缓存可见性；最终 QA 显式显示所选物件，修正旧截图中门被隐藏的问题，未改变生产可见性逻辑。

基础 HUD 的固定生成点可能与 RTS 门架重叠，用于检查图标及来源，不作为建造落点/导航验收。图鉴为实际渲染入口夹具，不新增玩家菜单项。离屏暂停截图的 FPS 不代表正常游戏性能。快活林木牌对应酒楼图标的现存差异仍开放；本批也不验收人物四向、战斗、手机或发布。

## 复现

```powershell
python -X utf8 -B tools/run_nonperson_icons_qa.py --baseline-from qa/nonperson_icons_20260927/baseline --work-root <工程外目录> --run
```

工具解析本机 Godot 配置，使用共享锁、私有用户目录、禁用 Steam，复制生产输入后重新导入。归档基线可跨 checkout 路径重放。`--baseline` 仅在修改前生产版本采集使用，不覆盖本归档。可选缓存仅限同本机来源与同引擎的已成功导入批次，仍重新导入。
