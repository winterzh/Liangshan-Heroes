此目录保存跨电脑检查需要的可追溯输入。它不在 Godot 运行时加载。

- `inventory_20260906.json`：从已提交基线 `374b2ecdd4f1240202ed3c8c5cf21eb350682d37` 的 Git 对象读取生产文件字节，逐一记录 69 个目标、36 个已有 PNG 的 Git blob/SHA256/尺寸和 33 个缺失目标。运行检查不会自动刷新它。
- 路由依据复用仓库现存 `tools/environment_production_mapping.template.json`，SHA256 `af1204a50a865096be47917440a36c67d9290f295fd5ee1ac2f8e000b1d441f1`，与历史文档相符。当前只添加文档已经记录的木墙 level3/level5 共用规则。

Git 对象提供的是**生产字节基线**，不能证明原画来源。四张地表的原图 SHA、生产 SHA 和网页会话有文档记录，但原 PNG、完整提示词及安装证据在本 checkout 未找到。其他目标同样逐项列出来源缺口。

更新清单必须依据新的、独立验收的提交和来源资料，审查每项差异，再修改验证工具固定的清单 SHA。不得运行“按当前文件自动更新预期”的流程来清除错误。`.gitattributes` 保持冻结清单的精确字节，避免系统换行转换造成哈希变化。
