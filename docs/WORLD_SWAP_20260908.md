# 经典据守世界替换与统一激活

run_world_swap把实际HELD经典30波世界同步捕获、重建并替换为可运行的新世界。它是内部同进程恢复事务：来源必须仍是SceneTree.current_scene且位于根节点，必须通过真实屏障健康检查；不接受调用方提供的任意存档和Steam局编号。玩家保存退出/继续入口、磁盘槽和跨进程持久局仍未接通，八战役适配及原整体验收要求不变。

prepare只读取旧世界，保留旧场景和全局光标；用当前受信内容/引擎身份及运行定义调用world_core.prepare。commit再次核对官方玩法与当前Steam服务的账号、活动局编号和计数器，在同一暂停非物理帧内绑定根状态/时钟、图腾退出计数并挂载新世界。Unit的died/story_resolved只连接新Battle，所有图已绑定后才释放共享Unit/Fx占位，依次恢复Unit、视觉、雾、世界显示、镜头、环境和HUD；最后创建真实物理步屏障并激活恢复时钟和Battle处理标志。

所有可能返回失败的组件阶段完成前，旧世界仍保留。失败时释放新世界和身份，重新把旧镜头设为current，旧世界保持HELD，调用方可以继续操作旧屏障；未提前提交场景、开始Steam新局、重放技能或部署地图/单位。成功后切换current_scene、释放旧世界，随后安装新光标，避免旧场景退出清除新光标。保留原先用户暂停状态与受信main.tscn重开路径。handoff_world转移节点与身份的所有权；调用方保留返回identity，供再次捕获时解释历史编号。

当前Steam绑定仅继承同一真实源世界仍有效的内存局。测试环境run=0仍不计入，非零局需账号/统计就绪且未结算；不会伪造跨进程身份或把旧局编号导入新进程。真实账号、持久回执/outbox及跨进程统计防重仍是后续必做项。
