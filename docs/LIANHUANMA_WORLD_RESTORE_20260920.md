# 连环马内部世界恢复：首批接入

起点为 stable 分支 `4b583c84a7303ad75ca4e296c69e32d60144238d`。本机先快进同步 9 月 18 日操作修复，再以 Godot 4.6.3 原生 Windows 验证。连环马本批范围是内部组件与跨进程保存恢复；玩家入口保持关闭。

## 实现

- 注册固定 `campaign_level4_v1`，只接受当前安装的连环马脚本、64×60 平原地图、章节环境和明确的模式旗标。工厂直接恢复已审计字段，不调用部署或开战回调。
- 单位契约绑定宋江、徐宁、呼延灼、韩滔、12 名连环马骑兵及章节引用；核验阵列归属、破阵/死亡计数、在场身份与败退/被擒结果。错关、重复骑兵引用、篡改波次和死亡计数在安装前拒绝。
- 接通章节单位图、景物、任务界面及普通视觉分区。破阵瞬态图只允许安装资源 `lian:broken_cavalry` 的固定尺寸、足点和生命周期。
- 既有江州、野猪林、快活林 QA 的“未接入章节拒绝”改为仍未接入的高俅，保留拒绝覆盖。

## 验证方法与边界

`tools/run_controls_update_qa.py` 冻结白名单源码到 checkout 外的新目录，使用独立 `LSH-*` 存档目录并禁用 Steam；验证前后核对源码 SHA。默认执行 122 项输入、95 项战斗、32 项战役回归；`--level4` 增加三个独立进程，`--prior-level3` 运行既有祝家庄 full 用例，`--export` 导出并实际启动诊断 EXE。

连环马组件八个检查点为：初始、付费招募队列、北路六骑出阵、真实规则触发破阵、骑兵死亡、呼延灼败退/韩滔被擒、训练假人生成、恢复后继续运行再保存。破阵采用受控摆位和真实钩镰规则，角色结果采用伤害回调，均属于夹具，不计自然通关。每阶段实际落盘、卸载、安装和再存档，对照单位、关卡、地图、随机数；任务阶段年龄按生产墙钟在实测安装区间内增长，其余任务状态严格一致。

跨进程另起保存进程与继续进程，继续后运行 40 个物理帧并另存。组件各槽清空测试对象的续玩收据以隔离世界快照检查；本批不验收同一局收据生命周期、奖励、自然胜利或终局旧槽拒绝。后续必须补完整自然路线并接入既有完整世界默认驱动。

原生截图在暂停状态等待容器排版后采集，并核验消息行高度与文字最小高度一致。立刻截取恢复首帧可能看到尚未完成排版的消息框；该首帧不能用作稳定视觉验收。目检范围及最终数字以 [本批 QA](../qa/level4_world_restore_20260920/README.md) 为准。

## 复现

在配置好 `godot.local.txt` 或 `GODOT_PATH` 的 Windows checkout 运行：

```powershell
py -3 -X utf8 -B tools/run_controls_update_qa.py --run --level4 --prior-level3 --export --out D:\CodexTemp\lian_restore_new_run
```

输出目录必须不存在。默认重新导入；可用 `--cache-from` 指向引擎及美术来源 SHA 已核验且成功导入的旧批，仅复用纹理导入缓存，源码与用户目录仍重新冻结。此验证允许其他工程运行，只能支持功能结论，不能作为性能测试。诊断 EXE 使用私有项目名称和用户目录，不能拿它直接发布。
