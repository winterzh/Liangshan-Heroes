## Steam 统计

生产启动先将账号统计与本机战斗记录合并，保留较大的累计值。每局使用持久身份和已计入击杀上限，重启后重放旧进度不会重复计数；结束记录持久化后才允许结算。SDK 写入使用累计目标并限速重试；不把无请求编号的回调当作特定保存的确认。

Steam 返回统计校正时立即停止当前进程计入；下次启动必须获得同账号、完整且类型有效的统计读回，才能按服务器值恢复。旧局身份保留为已结束，不恢复旧的被校正累计值。读回或磁盘事务失败时保留数据并停止同步。

## 导出包实机发现问题（正在修复）

候选 `20260924_101559_f8ed14fb` 通过 1136 项打包/启动检查，但正式 EXE 的实际保存被拒绝；Steam 开启与关闭均复现。相同编译包在编辑器宿主中可保存。该候选不得发布。已增加只含错误码、恢复方向和引擎版本的本地错误记录，用于定位正式模板差异，不写入账号或战斗内容。

诊断候选 `20260924_103128_adb9d0c1` 的正式 EXE 记录到 `DISPLAY_CONTAINER`。Godot 4.6.3 的 `CallableCustomMethodPointerBase::get_method` 在非 DEBUG 模板中返回空名称，现有校验误把引擎连接当作额外回调。修复仅兼容正式模板的空名称，仍要求有效自定义回调、零调用参数、无 unbind 包装，并由调用处核对信号、原生目标、连接标志与绑定参数。正式 EXE 保存/重启验收尚在进行。

候选 `20260924_105434_a1052230` 的正式 EXE 已成功写入 Steam 绑定存档并正常退出，但实际鼠标续玩触发 `PAUSED_RESTORE_REQUIRED`，拒绝后存档 SHA 不变。原因是原 `call_deferred` 可能在物理帧末执行；恢复现改为等待 `process_frame`，保留底层暂停/物理帧校验，并新增物理帧发起续玩的流程用例。该候选仍不可发布，最终包待验。
