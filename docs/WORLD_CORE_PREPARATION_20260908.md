# 经典据守战斗世界准备事务

从e8b4d496acb440d364da04898952cd5f26f7400d接续，新增内部 `scripts/run_battle_world_core.gd`，把现有状态组件接到同一个实际Battle捕获和离树准备事务。正式接入的是R5受测字节及原生导入生成的UID。它尚不能挂载或继续整场战斗；没有玩家存档槽或菜单入口。

## 接口和顺序

受信宿主传入当前内容/引擎身份、defs/abilities/items及已有受信纹理对象。存档不提供脚本、资源路径或工厂；当前定义从受信运行环境传入，不从保存数据构造。`capture`要求实际Battle在暂停树中持有完整步屏障，所有分区在同一同步调用中捕获。UnitGraph创建的唯一身份空间同时提供给根、效果和特效引用。

记录schema为 `classic_world_core_preparation_v1`，14个分区为map、fog、units、level、visual、root、rng、items、continuous、zones、meteor、remaining、casts、item_casts。只接受当前内容/引擎身份和精确分区集合；JSON编码大小限制64MiB，最终磁盘入口还必须在读取/解析前限制文件字节。

`prepare`要求暂停且不处于physics调用栈。先验证地图并拒绝当前未支持的显示要求，再创建离树、禁用且阻塞信号的Battle；依次安装地图数值、单位及稳定编号、经典关卡、玩法RNG、迷雾资源、受信景物、混合Fx图与六组效果/施法队列。单位保留原足迹，不重复注册地图阻塞；关卡不deploy/start，玩法RNG不额外取数。

根状态在此阶段只验证并返回pending_root。模拟时钟必须在最终安装/激活当帧绑定，不能提前恢复后等待多帧。新Battle没有RunClock和Steam局身份，也不调用新局初始化。prepare返回Unit/Fx/Fog的后续激活计划及地面火计数；世界兄弟顺序、其他显示/UI、Unit信号、根时钟、Steam续局和激活仍由完整世界事务负责。当前模块没有最终提交或接管所有权接口，调用者必须保留模块并调用dispose释放准备树。

prepare核对根/Unit实体分配器相等、根地面火计数与实际准备图相等。物品分配器必须大于活着/死亡中单位物品栏、hero_item_progress、触发冷却及两组道具队列中的全部已分配UID；重复活物品和冲突的历史归属拒绝。旧 `_uid_seq` 只是库存历史计数，不能当作全局物品UID。历史队列不会因当前物品缺失而提前删除，仍交由原消费者处理。

晚期分区失败会释放新Fx、身份占位对象及整个临时Battle；从不释放或修改源Battle。成功准备也必须显式dispose。捕获返回的identity由调用者负责释放，外部提供的retained_identity不由捕获失败路径擅自释放。

## 原生证据

R1无头运行在源迷雾 `_fog_tex.get_image()` 与 `_vision_img` 一致性检查处失败（TEXTURE_IMAGE_MISMATCH）。R2改为Windows/Forward+/Vulkan、RTX4060 Laptop后通过5811项；迷雾校验源码未改。这里确认的是本机两种运行方式的差异，未把无头失败掩盖成通过。

为支持真实纹理回读，overlay执行器新增显式 `--rendered-driver`：仅driver使用Forward+ Vulkan并最小化窗口，import和默认模式仍为headless；模式及实际命令写入收据，私有user://、来源/候选保护、公共锁、超时及子进程清理保持。驱动自行核对真实显示后端与显卡。测试最小化窗口，报告viewport为0×0，不是可见画面或像素排版验收。

R3补充测试的 `_check` 参数写错，driver解析失败；已保留原日志，修正后R4通过。R5进一步将单位顺序从数量检查加强为逐ID比较，并检查恢复后的新迷雾纹理、CPU图像及图层绑定。R3至R5生产候选相同，驱动不同。

最终R5为5823项，其中5778项是受保护来源SHA，45项是环境、结构、状态与回滚断言，不是5823个玩法场景：

- 真实经典FIGHT正常推进120个physics观察帧后，申请并等待真实HELD屏障；在同一时点捕获14分区并JSON往返。
- 新单位的root/active逐ID顺序、厅堂绑定、波次/计时、下一实体编号和玩法RNG一致；地图完整回读包含五张寻路表、足迹与景物。
- 迷雾逻辑数组/计时、CPU像素、GPU纹理回读及图层纹理引用一致；资源是新对象。准备树在额外4个process帧中保持不运行，源时钟与波次不变。
- 14分区逐个损坏时均拒绝，临时Battle和身份对象释放；引擎、实体分配器、地面火计数冲突分别拒绝。
- 合成历史道具队列引用UID900时，旧分配器拒绝；改为901后准备成功且保留队列。此例是明确构造的记录夹具，不是当前正式物品玩法验收。
- 最终原Battle仍存活且波次/时钟未变，成功准备树显式释放，原屏障释放；各轮来源、玩家目录、私有源码、候选保护均通过，子进程退出且锁释放。
