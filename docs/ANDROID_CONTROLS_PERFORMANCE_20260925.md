# Android 开局渲染与操作修复

本批基于 stable `3fe9eecf`，只同步源码，不改 2.0 版本号、APK、Release、更新服务器或 Steam。验证结论与原始收据见 [QA](../qa/android_controls_performance_20260925/README.md)。

## 托管

旧实现只清除英雄的 `auto_micro`，全托管等级 3 的下一轮 AI 又会恢复它。反复点按钮实际上重复同一个取消动作，信息聚合因此出现 ×2、×3 和未读 +1，并不是一次点击被持续重复执行。

现在桌面 T、Shift+T 与触屏共用 `Battle.set_heroes_managed()`：只处理本战斗存活己方英雄并去重；全选中已托管则取消，否则补齐选中英雄的托管。标签、按钮动作共用同一目标集，活动子组是士兵也不再与混选英雄脱节。只报告实际改变的数量，无变化不报成功。

从全托管取消英雄时，显式切换到设置面板可见的等级 2，同时退出自动镜头和自动经济。未选英雄原有托管不变；再次“托管军”只开启英雄托管，不悄悄恢复全自动经济/镜头。想恢复全托管需在设置选择等级 3。此操作不直接保存配置，但随后正常 `Settings.save()` 会保存当前等级；新战斗仍按原有模式规则初始化。不是独立的“仅本局、永不保存”偏好。

## 触屏布局

- 六英雄技能区新增安全区宽度 25% 上限，宽/高预算取较小值，保留每个技能至少 48 个逻辑单位的触控尺寸。极窄安全区优先保证触控下限。
- FPS 与菜单同排、处于战斗 HUD 上层；技能栏、资源和军情条避让其实际矩形。暂停/结算模态层仍更高。
- 顶部军情条按文字实际宽度收缩，最大 600 个逻辑单位，尊重顶部安全区。资源长文缩字至下限后截断，不压住 FPS/菜单。
- 没有删除被动技能槽、键盘操作或物品栏；触屏底栏仍不重复显示技能。

## 静态场景绘制

岸线与台地使用持久化有序网格：只合并相邻同纹理指令，保留透明绘制顺序、顶点颜色、纹理 UV 和细线的抗锯齿边缘。AtlasTexture 矩形保持原生绘制，并在前后断开批次，保留边距和裁剪语义。无效几何完整回退到原配方；阴影、芦苇、深度排序子节点和游戏逻辑不改。

抗锯齿几何对照 Godot 4.6.3 `renderer_canvas_cull.cpp`，来源及 MIT 声明保留在 helper 顶部。缓存只在首次绘制创建，后续重绘复用。`LSH_STATIC_SCENERY_BATCH=0` 在新进程中启用旧路径，供同源 A/B；默认启用优化。不把已缓存 CanvasItem 命令误认为 GPU 已合批，也不把 Compatibility 不支持的 2D MSAA 当作本次收益。

## 复现与边界

先以 `tools/run_rts_refinement_qa.py --godot <Godot 4.6.3> --out <全新外部目录> --visual` 冻结生产白名单、创建独占测试配置并运行逻辑/触屏矩阵。之后用 `tools/run_android_render_qa.py --godot <同一 Godot> --snapshot <上述目录> --out <另一个全新外部目录>` 串行运行静态图元与驻守开局 A/B。不得直接在玩家工程或玩家配置运行测试脚本，也不得并行启动第二个 Godot。

画面样例按原生像素尺寸渲染，但宿主为 macOS，不是 Android 驱动、触摸或温控实测。开局性能夹具暂停了模拟，不代表 60 波实战帧率；渲染 CPU 与帧间隔分别记录，GPU 返回 0 表示该计时不可用。仍需在用户手机/平板安装后确认持续帧率和手感。
