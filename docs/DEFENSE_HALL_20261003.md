# 据守大厅外观与 HUD 来源修复

经典与自定义据守复用第五幕梁山静态忠义堂，但玩法建筑原先按据守关卡查询场景纹理，查询不到时仍绘制旧建筑，形成两套外观重叠。现让精确归属的玩法大厅使用同一场景来源，既有静态视觉分支抑制重复绘制；界面头像同步该来源，不改变位置、血量、规则或关卡身份。

## 实现范围

- `scripts/levels/skirmish.gd` 的 `decorate()` 登记 `liangshan_hall_cell`；该元数据键已在现有 `run_map_state.gd` 中序列化，不新增存档格式。
- `scripts/unit.gd` 新增 `_campaign_environment_art_level_id()`：只接受经典/自定义据守的 `hall`、明确静态归属及 `zhongyi_hall` 路由，地图环境来源为 `level5`，位置精确匹配大厅格，并存在静态场景层。其他建筑或错误位置、来源、静态标记保留原关卡作用域。
- 场景纹理、脚点标定和文字矩形共用该有效来源；玩法关卡 ID、全局人物图标和其他建筑路径不变。未新增或重画生产位图。

## 本轮验证

最终隔离 Godot 4.6.3：**51/51** 通过、**3393** 输入及私有副本零漂移。真实经典据守、自定义据守和第五幕验证唯一静态大厅、位置/来源、HUD、选区及元数据无副作用；负例包括普通动态建筑、偏移位置、其他建筑键、错误地图来源、无静态层及错误路由/状态/文字表面。三张 1280×720 截图核对完成；经典图与已目检首轮完全同 SHA，自定义和第五幕最终图直接目检。

初次预检因其他项目引擎占用暂缓，其自行结束后测试。首轮测试将自定义配置设为空，生产工厂按正常规则回退经典关卡，51 项中 6 项身份/作用域断言失败；将夹具改为非空合法配置后重跑。复用首轮成功导入的同引擎缓存，但源码、脚本类缓存和私有存档重新建立且重新导入。首轮日志、收据、报告和原夹具保存，不把失败改写成通过。

最终导入/图形进程均退出 0，无脚本或引擎错误。图形日志保留 Compatibility/GLES3 不支持 2D MSAA 的平台警告，不宣称警告为零。证据见 [QA](../qa/defense_hall_20261003/README.md)。

## 复验与交付

```powershell

python -X utf8 -B tools/run_defense_hall_qa.py --work-root <工程外QA目录>

```
