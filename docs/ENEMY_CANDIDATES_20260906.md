# 索敌候选按实时阵营提前筛选

基线 `bf3e1a66a619d9bccfe93454df991b31a23889cb`。Unit 原先把邻格所有单位复制到候选数组，再逐个排除友军；友军密集阵型反复产生大数组。

生产改动只有两处：Battle 新增 `enemy_candidates_near`，在收集阶段排除无效实例和同阵营单位；Unit `_acquire` 优先使用此入口，兼容只有两参数 `units_near` 的既有适配器。原始 `units_near` 和网格重建保持。

每次查询读取当前 faction，不创建跨查询阵营缓存；空网格仍从当前 units 列表收集。保留网格遍历和桶内相对顺序、重复敌人条目，因此同分选择顺序保持。Unit 原来的自己/阵营/生命/资源/剧情/隐身/芦苇/驻守/距离/放弃冷却过滤以及评分保持，未调整战斗规则。提前过滤额外检查会让全是敌人的候选略慢，保留原防御性检查以兼容旧查询适配器。

## 验证范围

- 专项 68 项：4,032 次候选数组按对象及顺序与旧入口过滤结果一致，覆盖反转/重复/空桶、移动后未重建、阵营转换、无效对象、空网格。输入网格和列表成员/次序保持。
- 1,575 次完整旧/新 `_acquire` 对照：同一个真实 Unit 从相同快照执行，直接比较选中对象，并比较所有脚本变量和必要 Node2D 状态的序列化值。32 种场景包括同分/优先级/隐身/剧情禁选/放弃/迷雾、四种 stance、六种范围和两种 closest 模式；另有 float32 范围边界、旧适配器、禁用范围及 12 个计时目标对照。冻结完整旧方法 SHA256 `0309d0fcd3acc29bc5a41b8f35aad827b14d383a9ee79c32c37ba887da29f7e7`。
- AI 173、追击 44、网格 142、实际攻击 23，连同专项共 **450 项**。追击含 720 步真实移动/重新索敌；攻击用真实命令触发靠近与伤害并检查据守。网格覆盖八关部署与驻守合成兵群，不计作八关玩家通关。
- 初次探针选错会重启的短战役场景，后改用独立 arena；初次专项在 arena 直接打开 fog 但未初始化视野数组，日志出现脚本错误，已通过真实 `_init_fog` 修正并重跑。最终六个进程退出码 0 且日志无脚本错误；初次错误不算通过，原日志单列保留。

## 测量与取舍

正常驻守战预热 3 秒后约 10 秒计数：6,678 次索敌，4,712 次邻格只有友军（70.6%）；原始邻格条目 924,570 个，进入后续过滤/评分的候选 6,280 个，减少 99.3%。混合组中绝大多数也是友军。此为一次实际战斗的插桩分布，不能直接换算耗时或 FPS。

前置 Unit 分段计时只用于定位方向：移动/索敌状态分支大于零值状态计时，计时段与方法包装有嵌套和探针成本，不能直接相加或当正常帧率。本轮未引入状态计时批处理或持久投影缓存；临时插桩均恢复原字节。
