# 持久局身份与完整世界会话联调

## 已接入的内部路径

steam_local_run_session把独立Ledger、局token、待提交累计击杀和终局意图连接起来。SteamService新增显式内部启用接口_open_persistent_runs，并在该模式下把真实Battle的累计死亡/终局回调交给本机收据。run_world_session保存前先确认同一局收据落盘，再写世界槽；恢复使用当前账号打开的独立收据验证token、玩法、高水位、代数与终局状态，沿用原token而分配新的进程内handle。旧槽不会覆盖或重建统计历史。

该模式尚未在正常启动自动启用。它启用后不调用SetStat/SetAchievement/StoreStats，也不把无批次身份的SDK回调当成收据代数确认；状态文字明确本机保存、Steam同步未接通。原普通Steam模式仍沿用现有SDK路径。持续outbox/SDK发布的迟到回调、校正与重启窗口、正常启动接入以及玩家保存退出/继续按钮仍需完成。此批不能称为真实Steam账号同步或玩家续玩已经上线。

## 写入与恢复顺序

新局token在Ledger成功落盘后才关联本机handle；公开begin_run保留现有官方玩法与test_environment准入。本机适配器的observe和queue_terminal只更新内存意图，避免在死亡物理帧内执行文件IO。空闲处理每秒最多检查一次待提交意图，或保存/切换新局/退出前显式checkpoint；checkpoint拒绝在物理帧调用。只有超过已持久高水位的累计值才新加统计，终局意图第一次确定后不接受重复或相反结算。击杀与终局分别提交，二者之间的中断仍保留已确认击杀且不会产生第二次已确认胜场。

槽binding新增steam变体，精确6字段：kind、owner、token、credited_kills、generation、receipt_sha256。已有uncredited变体和槽schema v1继续可读，保持严格字段/类型/规范JSON校验。保存时受信账号来自当前SteamService，目录由启动代码提供；任何槽字段都不决定账号、文件路径或脚本。世界累计值不得大于槽记录的已确认高水位；恢复时独立收据代数不能倒退，同代SHA必须匹配，最新该局高水位不能低于保存时值，已终局必须拒绝。

prepare_restore在完整禁用世界准备后验证绑定，commit_restore在组件激活后再读当前收据、核对账号与未终局，成功后无yield/信号/SDK或文件IO地转移局映射和世界所有权。token留在外部会话，Battle只得到本进程handle。绑定校验失败由原Core回滚新世界，实际菜单保留；收据失败发生在写槽之前，原槽和HELD世界保留。已失败的本机宿主保守停止后续读写，当前进程不会忽略错误重建空历史。

内部启用拒绝已有活动局、SDK脏状态/在途请求及未就绪账号。当前读取种子仅用于新收据；已有收据从磁盘恢复自己的统计和墓碑，不被旧SDK缓存种子覆盖。SDK结果8在本机模式触发本地失效并停止计入；回调与失效落盘之间的崩溃原子性并未解决，真实发布器接入仍受该门槛约束。此模式不提供多设备独立增量合并或服务端已确认的承诺。
