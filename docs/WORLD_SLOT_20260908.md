# 经典据守单槽与跨进程世界恢复

## 当前接口与范围

新增run_slot_store与run_world_session内部接口，将已实现的完整Battle世界图保存到独立单槽，并在新的原生游戏进程从实际菜单安装恢复世界。当前支持官方经典30波且Steam局编号为0的未计统计世界；有统计的Steam局在写槽前明确拒绝PERSISTENT_STEAM_BINDING_REQUIRED。正常菜单、暂停菜单和autoload尚未调用这些接口，玩家“保存退出/继续本局”尚未开放。这是通向统一会话的中间实现，不能代替原定持久Steam局身份、outbox及完整八关的最终交付。

run_world_session(trusted, runtime, slot_root)由当前安装提供内容/引擎身份与运行定义，禁止从槽加载脚本、路径或自报受信身份。save_held要求实际当前Battle、官方经典30波上下文与完整物理步HELD屏障；保存20个世界分区、根节点激活/几何、6个Campaign选项、原暂停意图与未计统计绑定。它不释放或退出当前世界，只有文件关闭回读、链验证与解锁全部成功才返回成功。写入失败时当前战斗保留，调用方负责HELD生命周期；失败残留可能阻止继续写入，未实现玩家错误恢复按钮。

prepare_restore要求实际当前菜单及暂停状态，读取并验证槽，用当前受信定义构造禁用世界。commit_restore再次检查菜单、Steam租约、Campaign选项和磁盘SHA/内容，再设置当前局倍率与模式，挂载并激活所有组件，最后转移世界和稳定身份所有权、释放旧菜单。中间失败撤销新世界，恢复自身更改的Campaign选项和菜单画布；在提交前检测到外部选项改变时保留外部新值。恢复沿用当前Settings游戏速度，不重新部署、不调用Steam.begin_run。返回的identity由会话调用者保留，下一次保存用于识别死亡实体。

## 文件合同与兼容

run_snapshot_store抽取原Steam收据的双快照文件事务；steam_receipt_store成为只定义magic和Receipt校验器的子类。原Steam v1路径、9字段字符串封套、generation到revision映射、规范JSON、哈希链、排他写锁、关闭回读、重命名、保留最近两份及死进程恢复流程保持兼容，最大16MiB。新槽使用独立magic LH_CLASSIC_CONTINUE_SLOT、schema classic_continue_slot_v1，默认user://continue/v1/5088120/1；末级1是槽编号，不是Steam账号。槽封套上限64MiB，generation为1..2147483647，世界模型逐分区验证由Core.prepare执行。恢复不猜测旧schema或缺失字段。

写入前检查大小，锁内再次比较期望代数/SHA，完成待写文件回读后重命名并校验正式文件；死写者需实际PID已终止才能恢复。合法完整pending可向前恢复，损坏字节或未知残留拒绝，不回退到较旧槽。flush与关闭回读、OS.kill均不证明断电持久性；恢复操作本身再次被杀、空/损坏锁等情况仍保守阻断，后续恢复设计保留。
