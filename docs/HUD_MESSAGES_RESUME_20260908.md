# HUD 消息状态与动画恢复

world core内部schema v5增加第18分区hud_messages。新增run_hud_messages_state保存最多50条消息及合并次数、未读数、展开状态、水平/垂直阅读位置、待滚到底部动作，以及最多3条即时提示的顺序、次数、淡入标志、停留时长、已过时间和当前透明度。core在实际HELD屏障下捕获，prepare完整校验并返回pending_hud_messages；目标HUD尚由下一阶段工厂构造，本分区不等于完整HUD或战斗已经可继续。

## 行为与安装合同

HUD保留原有限线性Tween：新提示淡入0.15秒、普通停留2.60秒、淡出0.25秒；重复提示直接全亮并停留2.75秒。全托管原有较短时长仍保留。构造函数记录当次时长和淡入方式，恢复重建同一受信Tween并用custom_step跳至保存的时间，不调用show_message重新发送、不增加未读或重复次数，也不因当前托管状态改变历史提示的剩余寿命。

Godot公开脚本API仅用于运行/有效性/循环次数和已过时间；不使用未绑定的C++ getter，也不是任意Tween反序列化。构造和seek依据[Godot Tween实现](https://github.com/godotengine/godot/blob/4.6/scene/animation/tween.cpp)。该合同仅用于当前HUD构造的固定动画，不能表达外部替换的自定义Tween。记录不允许脚本、资源、回调或任意持续时间。

原先await process_frame的滚动请求改为显式pending，由HUD原生_process消耗。因此HUD被屏障禁用期间，滚动请求也停止，恢复后才执行。阅读位置另在第一帧重新赋值，适应新建Container完成布局后的滚动范围；视口改变时由原生ScrollContainer按有效范围裁定。

restore要求已在暂停树中完成正常控件构建的全新HUD，HUD处理关闭且信号封锁；整份记录通过校验后才赋值和构建提示。activate_rows仅恢复新增提示及文字节点的默认处理/信号状态，保持HUD自身禁用，由最终安装事务统一开放输入。重复激活、节点被改动、坏记录拒绝。正式新局继续调用原HUD入口，不改变消息计数、条数、淡入淡出和信息按钮行为。
