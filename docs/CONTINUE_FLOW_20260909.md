# 2026-09-09 本地保存退出与菜单继续整合

后续审核补齐[本地终局收据](LOCAL_CONTINUE_LIFECYCLE_20260909.md)：未计Steam统计局现在也有独立的持久身份，结束记录先于结算写入，旧槽跨进程拒绝再次继续。保存请求与同一物理步终局相撞时取消未完成的捕获，恢复结算输入；磁盘失败保留终局和重试入口。旧`classic_continue_slot_v1`不猜测迁移，当前为v2。最终流程和历史批次以[QA记录](../qa/continue_flow_20260909/README.md)为准。

本批把经典30波的内部世界槽接入实际菜单和暂停界面，补齐覆盖确认、重复操作防护及失败恢复。生产入口仍关闭：正常启动和Steam安装包没有新增可用的保存/继续功能。只有编辑器二进制、Steam禁用及完全隔离的测试profile同时满足时，才通过相同界面和事务执行内部验证。

## 操作与事务

`ContinueFlow`集中协调菜单、HUD、Battle屏障和AppLifecycle。菜单读取成功后才替换当前场景；读取失败保留原菜单和槽文件。新开局不删除旧槽。保存前读取槽generation和文件SHA，覆盖提示绑定这一次观察结果，确认、捕获和持锁提交时再次核对，拒绝覆盖并发产生的新槽。取消默认获得键盘焦点。

有统计的世界仍须先通过独立统计收据绑定，再写战斗槽；未获得正式持久统计协议的正常Steam局不能绕过此要求。本次实际流程使用未计Steam统计的隔离世界，不能据此认定统计续玩已完成。

写入确认后才执行正常音频释放及退出流程。提交或解锁失败时保留原Session、写锁token、冻结proposal和暂停战斗，只能重试同一事务；不能先恢复游戏再用旧状态保存退出。所有权丢失或文件不可信时停止自动处理并保留文件。详细协议见[同进程事务重试](OWNED_SLOT_RETRY_20260909.md)。

屏障释放失败时错误界面继续可操作，普通返回和Esc不能清掉唯一的控制界面；提供恢复重试和带取消优先的退出确认。退出提示明确尚未确认保存的进度可能丢失。锁元数据已删除但目录残留等状态仍拒绝猜测修复，重启也不被宣称能修好坏档。

## 审核中修复的问题

- HUD创建按钮早于绑定Battle，回调现于点击时读取当前HUD的Battle，避免捕获空引用。
- 相机可能晚于氛围效果层更新，暂停后保存曾因屏幕变换陈旧被拒绝。屏障冻结后仅重算派生尺寸和逆变换，不推进phase、模拟时钟或玩法；原shader、结构和几何校验保留。
- 忙碌拦截曾阻断可信HUD内部准备态的暂停确认恢复；现在只有完整的暂停、禁用处理、阻断信号和准备标记同时成立时允许内部恢复。离场动作仍受忙碌保护。[专门回归](HUD_PAUSE_RESTORE_20260909.md)。
- 预屏障失败现在恢复调用前的暂停意图，覆盖已有槽的未暂停内部调用也不会因槽冲突留下意外暂停。
- 写入错误不再丢弃唯一的同进程事务所有权；严重释放错误不再留下无法操作的暂停画面。
