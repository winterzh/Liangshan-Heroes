# 祝家庄 RTS 可玩样板

基线：`7d22318af457b776a6c37daeb9146e59bec27899`。日期：2026-09-05。

用户同意以驻守经营与军队为基础重做战役后，首先实现祝家庄样板。源码入口为战役菜单“三打祝家庄”；沿用 `level3`、旧章节索引及故事顺序，注册脚本切到 `scripts/levels/level3_zhujiazhuang_rts.gd`。旧 `level3_zhujiazhuang.gd` 保留作原流程参考，已经不是菜单入口。

## 当前玩法

- 同一张64×56地图持续经营，不再跨阶段清空军队、建筑、钱粮和战果。开局前营、兵营、6名工人、宋江和林冲、2枪2弓；300金/200木、人口16/20、时代3。工人首次分配采集后，调度与建设由玩家负责。
- 复用共享刀枪弓马、民居、仓库、集市、防御建筑、作坊、撞车和投石车。聚义厅限定喽啰、宋江、林冲、花荣；孙立由探路/外围进展引入。英雄走经验学习，最多4员可训练/出场战斗英雄；受伤获救者不占人口、不能作战。
- 北面三名守军看守两处大储量金矿；清理后能自行派工采集并建仓库，资源不会自动入账。南面外营是来袭来源，拆营停止该处出兵与出击，已经出发的敌军保留。
- 敌军有独立金木池、4名真实采集工人和有限资源点；按对应普通兵成本扣费补兵，同时受36人口与18名生产部队上限约束。此样板没有自动重建营地和补充工人，经济能被长期削弱。外营被毁后仍可在庄内补防守兵；大营被毁则所有补兵停止。
- 首次出击约150游戏秒，需要至少3名已生产的预备兵；资源不足会推迟，后续以90秒为出击检查间隔。目标在前营与已夺北矿间交替，顶栏倒计时与出击消息提示来源。没有额外无限免费波次。
- 正门与偏门均可直接攻破；孙立也可到偏门标记接应内应开门。墙体视觉与阻挡使用新布局，没有绕地图边界穿过封闭庄墙的通路。门不再拥有不可攻破护盾。
- 核心胜利为摧毁祝家庄大营、救出时迁并护送到前营；宋江在前营标记确认收军。确认前可继续护送其余好汉，不强制全图清敌。宋江、时迁或前营损失则失败；扈三娘生擒、内应开门、七人生还是额外演义目标。
- 俘虏初始为中立角色，不提供玩家视野或挤占战斗英雄栏；解救后成为可选择的梁山伤员，由玩家下令撤回，不自动行军。

## 复用与必要修复

共享战斗/建筑数值不为本关改写；本局仅限制生产名单、补齐庄客生产成本/人口、定义俘虏状态。新的 `CampaignMission.set_title()` 只更新标题，保留已在办理的任务与标记；新战役不通过 `begin()` 重置阶段现场。场景墙体允许按地图元数据指定分段，旧关卡默认墙段保持原样。

回放发现既有树木实体占格与采集距离不一致：树半径13、工人半径10时旧距离29像素，寻路到相邻格中心为32像素、对角格约45像素，工人会不断寻路却无法伐木。`Unit._do_gather()` 对已登记实体占格的木材节点采用相邻格可达距离；金矿距离与独占规则保持原逻辑。此修复影响所有使用实体树木的经营模式，需要驻守/AI对战实际采集回归。

## 语义与兼容范围

“三打”在样板中呈现为扎营探路、外围争夺、攻庄救人三个持续战斗阶段，尚未重做原著逐日演出、林冲押送扈三娘、孙新换旗的独立演员动画。阶段可因自由打法提前推进，不要求第一次强制失败。新增外围营地、资源和出兵节奏是游戏化设计。

演义合同版本升到2，目前3项；原有已获印章按既有存档规则保留，不清空用户历史记录。旧版本4项目标的专属路线测试不再能证明当前样板；新样板使用独立测试入口，其他七关仍采用原逻辑。本轮没有增加战斗中途存档/检查点；重开从本关开始。

收据见 `qa/zhujiazhuang_rts_20260905/README.md`。contracts 为含显式边界夹具的工程检查，direct/inside 为保留真实敌军、花费、建造与生产的自动路线回放；不通过注入金木、冻结敌军、瞬杀或写胜利状态证明路线。地图总览图明确关闭迷雾用于布局检查，开局图使用正常迷雾。

最终39项工程/跨模式检查、68项既有核心回归、两条路线各4项通过；正面301.60、内应313.47游戏秒，分别演义2/3与3/3，核心均通关。两条当前回放都先取北矿和南营；不据此声称已经验证了跳过所有外围目标的快速强攻打法。内应在正门完整时从偏门入庄，撤离时军队另拆正门不影响该证据。两张1280×720实机图已目检。

本样板仍需真人首通、趣味、难度、操作量和完整长时性能验收。自动回放时长不能直接当作真人关卡时长；没有为了达到设计假设的20—30分钟增加空等或堆血。其余七关改造、中途重试、完整海军经营和既有美术来源缺口仍在后续范围。
