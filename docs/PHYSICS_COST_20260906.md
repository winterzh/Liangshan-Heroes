## 完整回调与呈现

完整 Battle 和 Unit `_physics_process` 分别包裹原方法一次，保留原函数正文、参数和返回顺序，不添加 RNG 调用。二者是不同节点的 SceneTree 回调；账本在 physics step 和实际 frame_post_draw 记录对应关系。timed 读取耗时，clockless 保留同样包装/账本但不计该回调时钟。增加脚本/对象和记录成本仍可能改变实例 ID 与墙钟演化，两者不是确定性重放，也不能把差值精确称为探针开销。

六组配对共 12 个 20 秒窗口完成，固定/自动镜头各 timed/clockless 三轮，运行和离线完整性检查全部通过。此前有一次 Settings 自动加载解析失败；原始失败日志及精确源码恢复收据单列。每个诊断批次的全部子进程退出后确认 Battle/Unit 原字节恢复，共同锁已释放。

## 同一运行的原生分项

另外一场固定镜头 20 秒诊断使用现有 `_prof_on` 标签，抑制周期打印，逐步保存九个 Battle 标签和 Unit `_phys_body`。计时字段在上一步完成后采集，结束明确补收最后一步；离线检查没有漏步或重复。运行选择 301–1505，共 1205 个测量物理步。

这些原生标签漏掉部分回调首尾，标签时钟/字典记录自身也有成本。它们属于上面完整回调的内部区间，不能再加到完整回调总数，也不能与另一进程的读数相加。后半程敌军减少使均值显著下降。

同一原生报告可按 process frame ID 分组：例如 ID 5619 包含八步，已记录分项累计 82.320 ms。父 M1 原始帧最大值为 134.945 ms，但父报告没有记录共同时钟起点和逐呈现 process ID，因此不能把这两个数字配成同一帧。不能用相邻序号或近似热身时间补造关联。

## 后续决定

优先确认分离内部“快照、profile_cells 建桶、逐对求解、写回”的成本分布。若单类型建桶潜在预算很小，则否定该候选并转向 Unit 粗分段，不再重复已否定的实例 ID、邻桶列表、二分或 z_index 微调。单分项省时必须经过完整行为回归和正常 60 秒重复窗口才可认作产品收益。

另一条独立诊断只记录首次音效合成/美术缓存加载与呈现时点，不提前播放或预热，以免改变全局随机流。两条诊断仍是准备中的归因实验，不是已采用的优化。M2 的持续 30 FPS 中间目标和 M5 的最终 60 FPS/P95/P99 门槛继续开放。
