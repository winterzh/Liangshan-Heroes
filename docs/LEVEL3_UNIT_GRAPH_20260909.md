# 祝家庄单位图恢复

`run_unit_graph.gd`新增显式祝家庄上下文和`level3_unit_graph_v1`；对应单位为`level3_unit_state_v1`。默认仍是经典`defense_unit_graph_v2`和`defense_unit_state_v2`，不接受经典槽携带战役角色状态。祝家庄只接受当前安装的固定Unit、Battle、Map、身份与编解码脚本。

捕获从真实祝家庄Level取得31字段记录；读取则先核对图索引，再验证同内容版本、同任务token的Level记录，派生扈三娘、两座门和七囚徒固定顺序的角色表。全部单位记录和角色活跃成员关系通过后才分配Unit。存档不能另传一套角色表绕过验证。

角色合同保留实际玩法允许的状态：囚徒被敌人攻击后`passive=false`、扈三娘低于1点血但尚未被擒、被擒后仍在活跃数组且可因迷雾隐藏、死亡囚徒仍留在根节点、营救后平民移动，以及孙立打开侧门后的撤离与解除阻挡。建筑`order_stop`并不清空所有队列，因此不擅自补写该状态。其他单位仍可能保留指向已被擒对象的延迟引用；这些引用由共享图保存。

恢复分离根节点顺序和活跃数组顺序，保留稳定实体ID、字段、引用、库存与元数据。新单位保持未挂载、禁用处理和阻塞信号；调用者仍须恢复Battle字段、地图、技能伤害、信号、RNG及任务界面后统一激活。此组件不调用关卡部署或奖励，不构成完整世界恢复。

已有经典全30波证据属于此前冻结来源，本批另跑短流程回归，不能将两者称为当前同包九种玩法验收。祝家庄仍待地图景物、任务标记与特效混排、Root/HUD跨帧安装、Session、持久章节结算及真实完整任务检查。玩家继续入口和Steam持久统计确认门槛不变。
