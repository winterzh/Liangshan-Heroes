# 官方恢复选型与祝家庄运行工厂

本批从已归档设计候选落实两个固定模块：`scripts/run_official_restore_profile.gd` 和 `scripts/run_level3_world_factory.gd`。选型仅识别已经实现适配的经典30波与官方祝家庄，不按关卡名称、存档脚本路径或全部八关注册表自动放行。它不激活世界、接入Steam或开放玩家入口。

选型接受精确的三字段上下文；JSON读取后的30.0/0.0只规范化到固定经典/祝家庄整数上下文。未知模式、额外字段、非法类型、内容版本或引擎身份不一致明确拒绝。关卡脚本来自当前安装的固定preload，并核对Campaign官方目录位置；捕获时还核对实际Campaign实例与关卡脚本。

祝家庄运行定义按正常开局顺序构建：基础Defs、安装内容覆盖、关卡可招募/庄兵成本/囚徒约束、技能视觉规则。所有写入都发生在私有字典，返回的环境建筑路由也独立复制；工厂不改变全局Art路由，不调用关卡部署、开场、过程或奖励回调。已恢复单位之外，后续生产与训练也必须使用这套对应关卡的运行定义。

关卡值恢复复用`run_campaign_level_state.gd`的31项显式字段、8个命名单位引用、7个有序单位数组及七囚徒固定槽约束。调用者先建立同一份稳定ID单位图，再将经过验证的记录、安装内容身份和同一任务token交给工厂；返回的是分离世界中的关卡实例，不重跑任务初始化。

当前仍需将UnitGraph与地图景物、任务标记与特效混排、Root/HUD跨帧安装、Session和持久结算接入完整世界。经典槽v3的本局托管设置、CAS与待写重试，以及Root技能序号先于特效绑定的修复必须保留。正式继续入口维持关闭；两个模块本身不能证明祝家庄保存后继续战斗。
