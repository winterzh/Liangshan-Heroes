# 暂停菜单：防止误丢本局进度

2026-09-06，从 `24d3250` 独立接续。另一个任务负责黄泥冈短篇和纲担美术，本批仅修改通用 HUD 与安卓返回键的转发。

此前暂停菜单里的“重新开始本局”“返回主菜单”“退出游戏”会直接执行，本局没有战斗快照，误点后无法接着原战场继续。本批先展示对应动作的确认页，说明本局战斗进度不会保存；战役模式同时说明已有章节解锁和通关记录会保留。

- 默认键盘焦点是“取消”，直接按 Enter 会返回暂停菜单。
- Esc、安卓返回键先取消确认，仍保持暂停；在普通暂停菜单再次返回才恢复战斗。
- 取消、关闭、重新打开暂停菜单都会清除待执行动作；重复确认回调只派发一次。
- 暂停遮罩置于战报、物品栏、技能提示之上，并移到 HUD 输入顺序末端，阻止点击穿到下层控件。确认页在 1280×720 与 960×540 均完整可见。
- 结算页“重打本关”保留直接重打。修改没有增加自动存档或中途读档；窗口关闭和系统强制结束的处理仍由原生命周期入口负责。

## 验证

Godot 4.6.3，Windows Vulkan Forward+ 实际渲染，专项 **55/55 PASS**：真实 GUI 鼠标与键盘事件覆盖三种动作的取消、默认 Enter、Esc、返回键；关卡重开与返回菜单走原始信号连接，实际释放旧场景并加载新场景。暂停期间单位坐标、生命、任务事件保持；章节记录、解锁和玩家战役存档字节保持。

另测竞技场的取消/继续、触屏 HUD 后置菜单按钮不穿透、已结算直接重打。退出及结算重打以信号计数拦截；没有真的终止应用。安卓返回通知与触屏布局在 Windows 模拟，不能替代 Android 真机操作验证。

实机图片发现战报盖住小窗口确认页后修正了层级，最终两张原始截图已人工检查。过程中的测试脚本类型错误和桌面不存在触屏菜单按钮的夹具错误均先失败后修正，未计入通过报告。
