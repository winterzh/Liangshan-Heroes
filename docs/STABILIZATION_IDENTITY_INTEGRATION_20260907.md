# 稳定实体编号正式接入

2026-09-07，本批已把24文件稳定编号候选与驻守关卡状态v2合计25份脚本接入生产，逐文件与实际受测候选SHA一致。完成86项原生身份行为、45项驻守桥接行为，以及经典30波模式和八关共9个正常开局案例。没有新增继续本局入口或增加正式恢复组件数量，仍需完整根状态、模拟屏障、效果图、磁盘事务与菜单接入。

## 代码行为

Battle为每次出生分配不重用的正int64 `entity_id`，先领取编号再构造单位；死亡、清场和构造失败不回收编号。`next_entity_id`保留精确整数边界，以十进制文本进入图记录，恢复图先验证全部引用，再返回待安装的allocator。已故障的Battle拒绝RNG和实体图捕获。

单位排序、分离相位、自动经济对象表、章节实体键和末波位置表改用稳定编号。短期战斗target/source/hit对象引用仍通过原生ObjectID域显式映射，不把两类编号混用。Unit值与图schema升级为v2；驻守状态v2直接保存末波位置稳定键，并检查它小于已验证next，不再错误地编解码为退休ObjectID。历史位置可属于已死亡对象，next仅为高水位，不冒充完整出生历史。

出生失败向调用者传播。已付费生产退回本次对应金木且不推进完成计数；江州囚徒、林冲、高俅和演练骑等必需替换先创建成功再移除旧对象。任务action.done可能已由Mission先提交，因此此处采用故障停止保护，并不承诺整个任务原地回滚。未来保存入口必须在请求、完整捕获及提交前都检查世界健康。

主要方法和创建调用的静态范围见[身份候选原生QA](STABILIZATION_IDENTITY_NATIVE_QA_20260907.md)。部分长分号行展开及固定换行属于格式变化；正常成功路径的创建参数、源码顺序、RNG调用顺序保持，未调整兵力、波次、物理频率或游戏速度。

## 实际验证

86项身份行为使用真实离树Unit/Battle图及失败注入，覆盖正整数边界、死亡后不重用、付费退款、任务替换失败保留及故障拒绝。另有45项驻守桥接行为，覆盖稳定ID恰好等于另一Unit原生ObjectID的碰撞、超过2^53的next、两次JSON往返、恢复后真实末波纠偏消费和继续出生。源码SHA及私有目录检查另计，不以数千个文件摘要充当行为数。

9个正常开局每例使用新独立Godot进程、私有用户目录、生产`main.tscn`与真实`Battle._ready`，至少完成120个实际物理回调，检查所有已分配/活动单位的编号唯一性、归属和next单调性。经典据守按真实费用排队并等待14秒生产工人；连环马使用真实Mission操作、寻路和停留两次创建/替换演练骑，没有传送角色或直接调用部署来补过。

全部案例退出0，无脚本错误、警告或泄漏；真实玩家、原生产输入、候选与私有副本守护通过，Godot退出并释放锁后才进行生产复制。完整日志、驱动、候选原字节和复制收据见[本批QA](../qa/stabilization_identity_integration_20260907/README.md)。旧CLI入口编译失败另保留在上一批身份QA，不重写为通过。

这些是普通开局和指定创建流程回归，未完成任何一关胜利、全部30波、1800秒运行、PCK或真人试玩。当前效果恢复草稿仍有原生反例，未随本批接入；性能基线仍绑定c0285f9，不能直接归给这一整合版本。
