# 黄泥冈世界保存与跨进程恢复（2026-09-12）

本批从 stable `19ec8c2c` 接续，黄泥冈内部整槽保存与六进程自然酒计路线现已通过：押队入场、白胜挑酒、下药配合和携担存档实际接续，最终三担送出、八人实到西口、4/4剧情目标与终局旧槽拒绝通过。玩家入口仍由九玩法统一交付门槛控制。

## 实现范围

- WorldCore 向所有已注册官方战役传递受信地图上下文；景物 adapter 仍只支持显式登记的黄泥冈和祝家庄。
- 黄泥冈使用独立 `level1_scenery_state_v1`，检查实际短篇脚本、48×40 丘陵地图、章节身份及景物绑定。祝家庄沿用原 schema 与门墙校验。
- 恢复只重建受控显示子树，不重跑部署、地图绘制或开局事件；材质、高度、导航和资源保护保持。树木所有权按生产 scoped-object 的 `is_tree` 标志识别，非树类环境道具不混入树冠列表。
- 原组件 QA 不再把 Session 拒绝保存当作通过；完整流程必须实际写入、恢复并安装世界。
- 黄泥冈枣车、提示牌、酒具使用固定类工厂与受信纹理登记，外部引用 token 从章节原始引用顺序生成；不从存档加载脚本或任意资源路径。
- 携担状态保留原始贡担单位：仍在单位根节点内，但隐藏、禁用且不在活动队列；校验 `cargo`、人物携带元数据、原贡担与旧处理模式一致。实际携担人的 `carrying_tribute` 必须为 `TYPE_INT`，再与担号比较；坏档负例分别使用 Dictionary、Array、float、null，要求明确拒绝，不能靠宽松数值比较或脚本错误阻断。无经济系统的黄泥冈 FIGHT 根状态纳入白名单。
- 暂停激活时同步人物与黄泥冈物件的画布高度；此前元数据正确，但画面要等解除暂停后的景物刷新才会就位。物件拒绝未记录的渲染覆盖、组、线程组和额外信号，提示牌重连唯一的固定语言回调。
- 恢复HUD选区后重算底栏展开状态，消息容器完成原生换行布局后重新定位；修复暂停时消息压到底部指挥栏、已选人物的详情仍收起的问题。
- 挑担人死亡后，实际掉担回调同步清除携担标记并重绘。否则贡担已落地、`cargo` 已清空，而尚未移除的死亡动画单位会触发孤立携担拒绝。组件夹具另存独立槽，检查死亡动画窗口的保存与恢复；此夹具不计自然路线。
- 保存屏障收集后续任务控件时，仅剔除已释放节点的旧记录；仍存活的控件继续保留首次记录的处理/信号标志。避免切换任务阶段后，已释放的旧控件混入恢复界面捕获注册表；不通过清空有效控件记录放宽屏障。

## 验证设计

`tools/level1_cross_process_qa.gd` 使用真实关卡、实际移动命令和正常任务计时，不传送人物、不直接改剧情阶段、不加速计时。六个进程依次保存未入齐的押队、途中挑酒人、进行中的下药配合、携担行军，最终完成三担撤离胜利，并从新进程拒绝终局前旧槽。

每次恢复在暂停下对照章节字段、计时器、单位 ID/位置/归属、角色引用、任务事件/动作、酒具和枣车数量；对照完整景物记录并验证激活后的信号状态。另检查错误章节与篡改景物上下文被拒绝。截图为原生视口输出。

死亡掉担组件夹具与上述自然路线分开：显式设置搬运阶段，将原始第一担摆到冈顶空地、晁盖摆在其取担点旁，避免开局押队占据点击位置；随后通过真实 `minimap_order` 地面命令、任务计时与 `take_damage` 死亡回调验证。此处有明确的阶段/位置布置，不能计作自然移动、酒计或完整关卡验收。

## 复现

配置本 checkout 的 `godot.local.txt` 后，用本机可用的 Python 3 运行：

```powershell
py -3 -X utf8 -B tools/run_level3_world_restore_qa.py --work-root E:/CodexTemp/huangnigang_restore --run
```

`--work-root` 可改为本机真实短路径；每次创建新私有工程和玩家目录，禁用 Steam、独占引擎锁。默认依次执行任务核心 `freeplay_core`、祝家庄同进程及跨进程回归、黄泥冈组件和六进程流程。`--cases` 可用于开发时聚焦诊断，不能把子集当作完整默认流程通过。

`--cache-from <此前私有运行目录>` 仅用于开发诊断，逐对核对素材与 `.import` 字节后复用 Godot 缓存；依然运行引擎导入并重新扫描源码，不复制玩家 profile。收据明确标识是否复用缓存。最终回归采用不带此选项的全新导入。
