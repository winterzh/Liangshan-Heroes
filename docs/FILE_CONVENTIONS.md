# 文件命名与格式约定

本约定面向后续新增和维护的文件。历史 QA、来源链和已被场景/工具/清单引用的路径视为证据或接口；不得只为统一外观而批量改名、转码或删除。

## 命名

- `scripts/`、`tools/`、`assets/` 中新增的一方文件和目录使用 ASCII 小写 `snake_case`；名称表达用途，避免临时编号、空格和依赖本机的绝对路径。
- `docs/` 的常设说明使用大写主题名，如 `SOURCE_SETUP.md`；带日期的交付记录使用 `TOPIC_YYYYMMDD.md`。长期索引保持 `DIRECTORY_INDEX.md`。
- 新 QA 批次使用 `qa/<topic>_YYYYMMDD/`，根目录放 `README.md` 作为结论入口；单次执行保留时间戳和短运行 ID，原始日志、截图、清单及失败记录不覆盖。
- 新工坊/商店交付按现有 `marketing/<topic>_YYYYMMDD/` 分批保存；公开正文与草稿用不同文件名，不能互相覆盖。
- Godot 资源的大小写、扩展名和 `.uid` / `.import` 侧车文件属于资源引用的一部分；重命名前先查场景、脚本、清单和导入元数据中的引用，并同步更新。

## 格式

- 新增文本源码、文档和配置使用 UTF-8；换行规则遵循 `.gitattributes`。有特殊解析要求的脚本按其运行时要求保留编码标记。
- 叙述用 Markdown，结构化清单/收据用 JSON，表格数据用 CSV，程序源码保留语言原生扩展名。不要把同一份数据维护成多个可编辑的事实来源。
- 图片按内容用途选择 PNG（透明或需无损）或 JPEG（照片/截图）；已验收的来源图、生产图和 QA 截图不做有损重编码。Godot `.import` 与源图一同维护。
- 日志和原始工具输出保留原格式与字节；需要摘要时新增 README 或收据，不改写原始记录。

## 去重与历史文件

- 去重前同时核验 SHA-256、用途、引用和来源链。仅在确认副本不是 QA 冻结输入、生产来源、发行证据或工具依赖后，才可删除或改为单一来源。
- `qa/`、`assets/` 来源/历史目录中的内容即使字节完全一致，也可能分别证明不同批次的冻结输入或来源关系；默认保留。
- 本次盘点在 Git 索引中发现 1,925 组相同内容，涉及 10,613 个路径，其中 9,510 个路径属于 `qa/`。`docs/` Markdown 没有字节级重复文件。Git 对相同内容复用 blob 对象；工作目录中的 QA 副本仍按批次保留。本次未改名或删除这些证据文件。
