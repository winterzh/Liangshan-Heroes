# Steam 持久局统计回执候选

本批为完整续玩准备了独立于战斗存档的纯回执模型，并完成 Godot 4.6.3 原生验证：88 项模型检查、7 个独立夹具进程合计 45 项检查通过。尚未接入生产 `SteamService`、真实 SDK 或玩家保存槽，不计为已交付的继续本局功能。

模型固定账号、32 位十六进制局 token、官方模式上下文和严格 v2 schema。每局击杀保存历史最高已计入数量；旧档从10杀重放到20杀不增加，21杀只加1。胜负终局保留记录，重复结算不再增加胜场，已终局 token 不能重新开始。JSON 整数范围、generation、四项累计统计上限、1万局记录上限、未知字段、错误账号和模式均有拒绝检查；到达容量时拒绝新局登记，不删除旧去重记录。

所有变化先准备、持久化并回读、再由匹配SHA提交模型。`capture()`只用于保存数据，宿主必须通过`publish_targets()`获取可发往SDK的绝对目标；尚有未提交变化或服务端纠正时禁止发布。统计回执必须独立于战斗槽，读旧战斗槽不得同时回滚它。正常服务端读取按最高值合并一次，不能把历史累计量再加到本地。

收到Steam result 8后，模型立即阻止旧目标，依次要求持久化失效记录、进行新的服务端读取、持久化精确纠正值；此前读取的generation不能用于这次纠正，也不能在纠正后把旧最高值重放回来。旧局记录保留为终局，新局随后才允许计入。

## 实际验证及剩余宿主工作

跨进程夹具依次运行创建、读旧档、写结算意图后退出、恢复结算、写失效意图后退出、纠正、再次恢复纠正。均使用新私有用户目录及普通文件flush/close后正常进程退出；没有模拟断电，也没有声称文件替换是原子操作。真实玩家目录、模型源码、测试副本前后不变，所有子进程已退出、共同Godot锁释放。

首次夹具在恢复阶段出现一项失败：把模型已规范化的整数Dictionary与JSON原始浮点Dictionary直接比较。修正检查后分别比较模型前后值与磁盘原字节；模型未改，第二次从全新夹具完整重跑通过。失败、成功日志和对应输入均保留在[QA](../qa/steam_run_receipt_draft_20260907/README.md)。

生产宿主仍需实现串行写入、坏文件拒绝、事务中断恢复、账号目录隔离、Battle持久token及击杀高水位、正常SDK回调接入。当前存在明确未解决窗口：收到result 8回调之后、失效记录落盘之前进程退出；仅凭这个纯模型不能保证重启不重放旧目标。后续须在发送SDK写入前持久记录未决状态，并为重启后的不确定结果采用明确的服务端核对流程，不能以本批通过略过。

本机测试代码和复现说明在[固定草稿合同](../tools/contracts/steam_run_receipt_draft_20260907/README.md)。这批模型尚不处理多设备同时写、战斗图重建、成品PCK或真正Steam账号的统计。后续接入必须重新以实际整合源码验证。
