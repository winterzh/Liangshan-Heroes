## 墙体

原先梁山部分墙段将原图的外接矩形压到斜向墙线；图片里的墙脚也有斜率，叠加后出现倾斜、逐段错台。另一方向及祝家庄还在拉伸旧图集中的小条，材质和柱高不一致，留下像斜坡的灰色底边。

现在复用已在库的无字木墙 `stockade_segment.png`，以512像素原图两根端柱的脚点 `(185,264)` 与 `(331,342)` 对齐实际地图端点。垂直方向保持竖直，柱高独立于透明画布大小。源PNG及alpha均未修改，SHA-256仍为 `e1f807ef74b32a7bd16bc14705a1436938b6942da34018f96294d11a834a0c44`。

梁山故事场景与驻守战的两条墙轴统一用该资源，并扩大单段跨度，避免把粗木柱挤成细条。祝家庄也显式复用该无文字构件；路由只新增 `level3`，原 `level5` 保留，其他章节/竞技场无此权限，大名府仍用砖墙。冻结清单的原始生产路径没有变化，静态合同记录了这一项有来源校验的用途扩展。

导航地形、门的碰撞和任务标记保持原有坐标。两座祝家庄门的四个接缝已按实际端点验证；墙后单位遮挡范围随完整柱高调整，实际点选和透明恢复通过。重新启动 `Play.cmd` 并重开祝家庄、三败高太尉或驻守战，即可载入修正。六张固定镜头对照图覆盖远景、门口和转角；它们不代表全关美术或开门动画完成。

## 船坞与训练

`scripts/naval_production.gd` 是关卡明确启用的造船定义与下水选择器。普通全局兵种没有被改成水军，也没有向现有驻守/旧高俅菜单增加船坞。

| 项目 | 当前底层规则 |
|---|---|
| 船坞 | 岸上3×3地基，100金100木、工匠实际施工30秒、900生命；复用旧码头图 |
| 普通梁山战船 | 90金65木、28秒、3人口；沿用现有船身、四向入口及水域移动定义 |
| 选址 | 地基走陆地规则，相邻水面必须容纳船的碰撞范围；预览与落地使用同一检查 |
| 下水 | 建造时固定泊位，完成后只在该泊位附近合法水域寻找空位；不用全图“最近开放格”兜底 |
| 堵口 | 地形或船只占满泊位时，完成的队首停在0秒，保留船、后续队列和人口预约，每0.5游戏秒重试 |
| 取消 | 队首或队尾分别全额退费；取消已完成队首清除等待状态，新订单仍需完整训练时间 |
| 集结 | 使用实际玩家右键集结点，生成后按已有水路寻路移动 |
| 维修与重建 | 工匠真实维修并付材料；建筑毁坏后停止生产、释放占地，允许重建。被毁建筑的未完队列按原有建筑损失规则消失，不退款 |

`Battle.on_unit_trained()` 现在仅在成功生成后返回成功，`Unit` 收到成功才移除队首。普通陆军仍选陆地出生格；共享取消和HUD新增等待反馈。受控测试使用真实建造、训练、集结、取消和维修命令；预算、地形和毁坏情况是明确的边界夹具。

船坞目前只有验证入口，尚不能据此称高俅RTS可玩。下一步是在持续地图上接入经营、付费舰队、岸军和有限敌军补充，再改诱舰、火攻与实际押俘回堂；营地与军队不能被阶段切换清空。新关还需要资源/船坞地点、兵力与难度调试、两条真实通关路线及真人试玩。

## 验证与边界

完整结果、实际日志、失败尝试、截图和输入哈希在 [本批QA](../qa/wall_naval_20260906/README.md)。船坞57项、墙体46项、孙立接应22项均通过，并完成共享核心、陆水远程路径、经营跨模式及环境路由回归。驻守墙角在1倍游戏时间、1440×900、RTX3070Ti的预热后10秒最终窗口，P95/P99为15.613/21.011毫秒；这是27单位的非战斗高峰短窗，P99超过单帧16.7毫秒，不能声称稳定60FPS，也不能代替30波或30分钟稳定性。

本机缺少历史环境静态合同所引用的 `environment_batch_manifest.json`，因此没有声称完整冻结清单静态门禁通过。另做了相对提交基线的全部路由表对比，验证只有木墙的 `level3` 用途增加，794项运行路由检查通过。后续需恢复历史输入或迁移为当前自包含清单。

角色四向本批未新增；新角色候选的透明处理选择仍待回复。尚未达到可售版本验收，没有导出、合并main或操作Steam。
