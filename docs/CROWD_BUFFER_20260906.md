# 密集队列的分离数据缓冲

2026-09-06，基线 `4589c8584d2b091872986ffb5cfa8a19ce72f617`。生产新增 `scripts/crowd_separation.gd`，Battle增加分派条件，Unit没有本批改动。

64～320名机动单位、且网格平均每个非空桶超过2人时，先将本次分离使用的节点、位置、半径、移动类型及状态读入局部数组，再按原单位/桶/邻居顺序计算，最后写回改变的位置。位置使用PackedVector2Array，半径保留64位浮点；节点索引按实例ID去重，但处理顺序及重复邻居条目保留。也保留网格生成后退出主单位列表的邻居，避免漏掉原函数会处理的候选。

缓冲只活到本次同步函数返回，不跨帧保存状态。地图阻挡检查、移动/静止权重、携金工人的相位规则和精确重合的旧行为保持。Unit没有自定义位置设置器，函数内部也没有等待或逐对触发玩法事件，因此将中间位置写入数组、在函数结束时发布最终位置，不改变下一系统读取的位置。

小队、分散队列及超过320人的既有分组路径仍使用原循环。探索表明，无条件准备数组会拖慢这些规模；缓存Unit实例ID单独几乎没有收益，已经撤回。此次分派按实测成本选择算法，没有降低物理频率或改变大场景的分组规则。
