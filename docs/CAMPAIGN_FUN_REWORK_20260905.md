# 八关战役趣味重做方案

日期：2026-09-05。检查基线：`ba4043ded36001d6c14fd0388e9796cc438b9d4e`。

状态：设计草案，未实现、未进行真人验收。用户反馈八关目前枯燥，要求研究怎样改得好玩。本方案暂以小队战术、英雄配合为主要方向，保留攻城、水战与决斗的区别；这不是用户已经确认的类型选择。本轮不把草案中的机制写成当前完成项。

## 1. 当前问题与源码依据

| 问题 | 已检查的当前实现 | 对体验的影响 |
| --- | --- | --- |
| 手动操作增加，决策没有相应增加 | `campaign_mission.gd` 的 `add_action` 登记人物、固定坐标、办理时长；`tick` 让人物停下并累计进度 | 玩家常在找正确的人、点正确的标记，答案已由提示给出 |
| 多人任务仍串行办理 | `_try_manual_action` 在 `active_action_id` 非空时直接返回，整个任务系统只有一个 `_actor` / `_progress` | 分队可以移动作战，但两个人不能同时办理不同现场动作，不利于同时救人、内外配合 |
| 章节推进经常清空整个现场任务 | `CampaignMission.begin()` 清空 actions、标记和当前办理者 | 要加入并行支线和持续威胁，需先处理其生命周期，不能只继续追加 `add_action` |
| 自由路线的反馈偏重完成记录 | 各关已有强攻/跳准备分支，常用 `miss_story_goal` 记录失去演义目标 | 选择的可见差异应更多体现在敌人位置、撤退安全、队友状态和可用支援 |
| 既有“深度”仍容易成为指定站位题 | 祝家庄有指定人物阵位，连环马有前6后6与指定换侧，黄泥冈有逐项酒计与搬担动作 | 玩家需要能自己布置、犯错后改招，而不是继续增加必须按顺序盖章的步骤 |
| 招式和分路已存在，不能当成新增成果 | 快活林已有圆形重击/长条冲撞和反击窗口；江州已有两路追兵、一次改道、22秒追击；大名府已有两条控制线 | 下一轮应把现有机制做出清晰反馈与可组合关系，避免重复实现 |

这些是代码与任务结构诊断；没有通过本轮桌面实玩测量玩家感受。用户的“枯燥”反馈是本次改造依据，旧自动通过记录不能抵消该反馈。

## 2. 统一的玩法目标

每关围绕“看清局势 → 作出安排 → 执行配合 → 应对变化 → 看见结果”组织。玩家应知道目标与危险，具体解法由自己决定。

1. **减少没有取舍的交接动作。** 无威胁、无资源取舍的换装、交代、登岸交接可压缩为短演出或一次清晰交互。取代它们的是实际接近、打断、控路、掩护与撤离。
2. **少数英雄有清楚的分工。** 沿用每关当前人物；先让突破、掩护、牵制、救援这些现有能力发挥作用。关键情节保留身份要求，普通开门、救援、搬运允许合理替补。
3. **敌人有可读的任务。** 部分敌兵负责守路、护卫、呼援或拦截，头顶提示/地面线说明目标与准备动作。玩家能通过走位、打断和分兵改变其结果。
4. **选择改变当局。** 绕路能得到接应或避开射界，拦住传令者能减少后续有限增援，提前救援能让队友更早参与。取舍在行动前可理解，结果在场上可观察。
5. **失误允许补救。** 暴露转强救、正路被堵转侧路、救援者倒下可换人；核心目标确已不可完成才失败。敌军支援设有限预算，避免无限刷兵拖时长。
6. **关键操作有明确回报。** 打断处决、骑兵冲锋落空、里应外合开门、火船引燃连舰应有短暂但清晰的声音、动画和战局变化；不以提示框代替战果。

不把八关统一拖到15—25分钟。野猪林可以是短篇开场，快活林是紧凑决斗；攻城与水战承载更长的部署和变化。所有时长只作首轮观察指标，最终以玩家是否持续作出有意义的选择判断。

参考：Subset Games 在 [Into the Breach 的 GDC 设计复盘](https://media.gdcvault.com/gdc2019/presentations/Into%20the%20Breach%20Postmortem%20Final.pdf) 中把可读性、减少无效耗时、清晰敌方意图和操纵战局作为设计约束。本项目借用这些原则，具体采用实时小队战术与水浒情节，不照搬其回合制规则。

## 3. 八关各自的乐趣

以下全部为提案。新增战术遭遇、敌人反应和路线效果属于游戏设计，不宣称逐项出自小说；既有原著目标、人物非致死结局和章节ID继续单独核对。

| 原著顺序 / 关卡 | 主打体验 | 基于现有玩法的具体改法 | 玩家要作出的决定 |
| --- | --- | --- | --- |
| 野猪林 / level6 | 看准机会、突然救人 | 压缩救人后的无威胁长路与重复歇脚确认；把两条暗跟路线做成可见的视线/遮挡差异；允许绕到前方埋伏或继续暗随，解差举棍有清楚前摇，成功拦棍形成开场高潮 | 贴近观察还是提前占位，何时现身；救后由玩家发一次明确相送命令，系统只维持四人队形 |
| 智取生辰纲 / level1 | 合谋与临场救场 | 保留药酒关键人物和动作因果，把固定操作串改成“引住杨志注意、把握用瓢机会、安排退路”的场上配合；暴露后仍能牵制押队、换人搬担；普通搬担不额外要求先到集合点确认方案 | 谁牵制、谁接近酒桶、谁留在退路；稳妥智取还是冒险抢时机，强夺后怎样分配搬运和护卫 |
| 醉打蒋门神 / level7 | 英雄对决、闪躲反打 | 沿用现有两种预警招式，强化拳脚命中和破绽反馈；酒路改为可选的酒力准备，少喝灵活、多喝重击强但动作更难控制；通过连续读招而非更多饮酒读条形成高潮 | 自己选择酒势，诱出哪种招式，用位移躲开后立刻反击，何时收势 |
| 江州劫法场 / level2 | 突袭、同时救人、边打边撤 | 拆除西街/南巷打卡前置；让李逵突破、花荣掩护、其他好汉救人能同时发生；可见传令者呼援、路口守军拦截；白龙庙接应和直奔码头有真实安全/时间取舍 | 先救谁，是否分兵拦住呼援，谁护送谁断后，什么时候收回断后队 |
| 三打祝家庄 / level3 | 侦察带来优势、里应外合 | 第一打找到的伏路和薄弱点在后两打继续有用；第二打牵制援军、制造侧翼；第三打让内应开门/救囚与外军佯攻并行，守军会向受压入口转移；把固定人物站格门槛换为实际控制效果 | 侦察哪一侧、保留哪支预备队、何时从佯攻转总攻，先救囚还是先控庄门 |
| 大破连环马 / level4 | 诱敌冲空、侧击破阵 | 保留现有钩镰与甲马减伤机制；由冲锋方向、阵型转向和钩镰侧击形成真实机会；后阵根据暴露的伏击侧调整方向，用可见部署提示代替固定强制换侧任务 | 诱饵何时撤、钩镰藏在哪侧、预备队是否提前暴露，冲锋落空后追击还是守中军 |
| 智取大名府 / level8 | 多路潜入、同时起事 | 换装/核验压缩为必要交互；时迁取火与柴进、乐和入牢并行，外军自行预部署；玩家决定何时放火，火号后守军调动能被利用；护民改变真实撤离压力 | 花时间补齐准备还是提前起事，怎样利用守军转移，救出二人后选哪条安全通道 |
| 三败高太尉 / level5 | 水陆协同、场面升级 | 三次进兵分别突出诱舰夹击、点燃连舰与护船撤退、压住护航后擒将；压缩无威胁的船上/岸上多次交接；火势、船群通道、岸上射界和接应位置直接影响战斗 | 放敌舰多深再合围，从哪里举火、何时撤接应船，集中火力破护航还是先保水道 |

第一版不增加全战役永久数值养成，也不要求新画面资源先全部到位。现有生产素材与既有技能足以验证战术循环；新素材仍按项目已有来源约定处理。

## 4. 首个样板：江州劫法场

建议先完成一条可直接试玩的江州路线，确认好玩后再做连环马。江州现有12个开局友方单位、两名囚犯、街巷与码头可以直接复用，不先扩地图或堆兵量。

### 玩家会经历什么

1. **开场就看到问题。** 刑台上的处决准备、两侧守路队和回衙门呼援的路线可见；开场短提示只说救宋江、戴宗并登船。前30秒内应出现一次实际布置选择，这是原型目标而非已测结果。
2. **可按自己的方式起事。** 李逵先动手继续满足对应演义目标；提前射击或侧路强救也能玩下去。取消“先分别在两个坐标确认，才开放起事”的必经仪式。
3. **救援和控制同时发生。** 两名救援者可同时解救不同囚犯。护卫若被击退/牵制，救援更安全；其他队员能去拦截呼援者。呼援者抵达衙门才触发一支预算固定的增援，路线与结果提前提示。
4. **撤退途中要调度。** 西巷狭窄但近，南巷宽但有可见射界。守军向已暴露的救援路线拦截，玩家可改走侧路或集中突破，不限制为一次点按钮改道。至少保留一条能通过战斗打开的出口，不因脚本关路造成必败。
5. **救到不等于撤出。** 白龙庙现有水军会合可以换来一段掩护；直赴码头节省时间但掩护较少。宋戴先登船后，玩家选择收回断后队、争取全员脱险；不以清空地图敌人为胜利条件。

传令者、守路分工与动态拦截是新增游戏化遭遇，不作为小说原文事实。是否保留120秒处决限时、从何时起算，应在首轮试玩后定；必须先显示计时来源和打断方法，避免阅读说明时无声消耗生存时间。

### 需要的最小实现

- `scripts/campaign_mission.gd`：增加显式启用的并行现场交互，每个交互有独立办理者、进度和一次性凭证。旧关卡默认维持旧行为，先由江州启用，避免八关同时更换合同。
- `scripts/levels/level2_jiangzhou.gd`：取消两个仅用于打卡的前置门锁；救人、拦呼援、掩护由实际单位状态判定；新增有限增援预算和能被打断的呼援过程。
- 任务面板/标记：显示两处救援进度、处决/呼援的威胁来源、可用出口；不自动选人、代走、代放技能或抢走相机。
- 首版复用现有移动、攻击、击退/控制、编队与Shift指令队列。可下令的战术暂停和中段重试作为后续单独任务，不声称已有，也不让它们阻塞样板验证。

### 先验证哪些问题

- 两个不同的明确玩家命令能同时救人；同一条群选命令不会误办两个动作。
- 一人改令、阵亡或离开范围只中断其本人办理；另一任务继续。
- 换阶段/重开/退出时不会留下旧任务、重复救人、重复出兵或抢回单位控制。
- 传令者被拦住与成功抵达的结果不同；增援总量受预算限制，不会无限刷兵。
- 正面、侧路以及半途改道至少各有一条可通过的路线；无须按原著也能基础获胜。
- 用真实移动、作战和交互入口完成路线；自动夹具不通过冻结敌人或直接写胜利标志来证明战术可行。
- 对比改前试玩，记录等待/纯赶路、目标是否理解、失败原因、是否用过第二种战术、是否愿意立刻重玩。首轮找3—5位首次玩家；“更好玩”由这些反馈验证，不由断言数量裁定。

## 5. 后续顺序与范围

1. 江州样板：验证分队、并行行动、清晰敌方意图和可补救撤离。
2. 连环马样板：验证布阵、冲锋前摇、诱敌与侧击能形成明显战果。
3. 祝家庄、大名府：复用稳定的并行机制，做两线协同与守军调动。
4. 黄泥冈、快活林、野猪林：分别压缩酒计打卡、强化决斗和打磨短篇开场。
5. 三败高太尉：在水陆寻路与性能预算内整合高潮，最后验证全战役难度曲线。

每完成一个样板再验收和向后扩展；本轮没有修改玩法、生成素材、导出或操作 Steam。来源证据同步缺口仍是独立工程事项，不应通过把历史素材重新判为已验收来推进本方案。
