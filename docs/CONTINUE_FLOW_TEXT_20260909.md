## 保存失败的提示边界

保存失败且没有待完成写入时，主流程保留以下通用反馈：

> 保存未能确认完成，当前战斗已保留。请检查存储后重试。

英日文只说明无法确认保存已完成以及当前战斗仍保留，不声称原存档未被改动：

- English: Could not confirm the save completed. The current battle is still open. Check storage and try again.
- 日本語: セーブの完了を確認できませんでした。現在の戦闘は保持されています。保存先を確認してから、もう一度お試しください。

磁盘可能已写入、但锁释放或回读未能确认时，当前 Flow 保留原 Session 与 HELD 战斗，并使用新增的 pending 专用提示。可安全重试时显示“重试保存”；不能安全重试时只提供明确退出。没有 pending 写入、但屏障暂时释放失败时使用“重试恢复战斗”。以下6键全部在当前 Flow 中实际引用，简中源键与繁中、英语、日语译文均非空，含义一致：

| 新增源键 | 实际分支 |
| --- | --- |
| 重试保存 | pending 写入且 `retryable=true` 的操作 |
| 重试恢复战斗 | 非 pending 的 HELD 释放重试 |
| 存档写入尚未完成，战斗已保持暂停。请检查存储后重试保存，或退出游戏。已有文件会保留。 | 可重试 pending 保存 |
| 存档状态暂时无法安全确认，战斗已保持暂停。请退出游戏并检查存储，已有文件会保留。 | 不可安全重试 pending 保存 |
| 战斗暂时无法安全恢复，已保持暂停。可以重试恢复，或退出游戏。尚未确认保存的进度可能丢失。 | 非 pending 的 HELD 错误 |
| 尚未确认保存的进度可能丢失。已有存档文件将保留。 | 退出失败战斗的二次确认正文 |

退出确认按空行分别翻译“退出游戏？”与新增正文，不把拼接后的整段当作一个新键。“已有文件会保留”不等于保存已成功或旧槽字节未变；不能据此把待确认写入当作完成。

“保存失败，当前战斗和原存档已保留。”仍按最初清单保留，当前 Flow 未调用；“读取失败，原存档已保留。”用于读取错误。调用方仅能在已确认满足保留条件的分支使用，不得把写入、解锁、确认阶段的所有错误统一映射为旧存档未变。

“存档已保存，正在退出…”仅用于保存已确认完成的退出阶段。“继续战斗”按返回当前战斗的语义保留，但当前 Flow 未调用；“继续上次战斗”实际用于读取继续槽，二者在英日文中也明确区分。
