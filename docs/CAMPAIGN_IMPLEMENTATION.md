## 已落地的公共机制

- 旧`LEVEL=N → levelN`不变，菜单与下一关另用`[level6,level1,level7,level2,level3,level4,level8,level5]`，八关全部可选；相机和测试按稳定ID查找。
- 每局独立`CampaignMission`管理核心目标、演义目标、阶段、现场交互和战报。任务按钮只负责定位现场，不代选人物、不派遣；`request_action()`只供自动回归夹具。手动办理必须同时有玩家明确点击的任务目标、同组共享的一次性 token，以及人物进入物理办理范围；一个动作消费 token 后全组清除，不能一条命令串办相邻任务。
- 点击半径只判断玩家指向哪个标记，物理办理半径只判断人物能否实际办理；多个有效标记按全局离点击点最近者认领。江州重叠办理范围的中点点击不会救出任何一人，精确点击戴宗和宋江必须使用两条独立命令。
- 有效的玩家移动、攻击、技能、物品、驻扎、维修、续建、新建或陷阱命令会取消正在办理的现场动作，但不会伪造任务完成；无效操作不取消。
- 演义目标有`pending / done / missed`三种状态，只有基础胜利结算时才把满足全部必要事件且未触发禁行事件的目标冻结为完成。战报把基础通关和演义复现分开；菜单按稳定关卡ID记录基础通关、单局最佳目标集合和演义印。多局结果不会取并集，不能用几次互相冲突的路线拼成一次原著满完成。
- 指定剧情单位的昏迷、制服、被擒、撤离、登船在死亡结算前处理，清除后续锁定、施法与命令，终态免伤；普通单位仍正常战斗死亡。真实持续伤害、暴击与同帧多次命中有单独验证。
- 陆地/水域有独立寻路域。出生、平滑、步进、编队、分离、击退、钩索、换位及建筑弹出都检查移动类型，不提供自由载客/甲板行走/全英雄游泳。修复同尺寸AStar重烘焙残留solid的问题。
- 跨日转场重新部署，清理旧单位、区域技能、投射物、冰墙占格与引用，只保留剧情标志。角色造型随当前单位，贴图/头像一致。普通与战役动画缓存均含动作和朝向；缺非终态动作优先保持同方向idle，`death/down`不拿idle冒充终态。所有可移动人物维护四象限，攻击、技能、物品和冲锋起手锁向；真实定向帧不镜像，旧无方向图仍兼容回退，各模式共用同一Unit/Battle入口。
- 新增每阶段游戏秒数、墙钟秒数、有效任务命令、自动重寻路和中断数。终局/换段关闭只记一次，中断包括取消未完成动作；仅在内存记录，由QA导出，不新增存档或遥测上传。
